# KayKit UI 키트 5차-B — 스킨 원판 방식 (목적 동일, 생성 2장)

> 5차-A(부위별 분해)와 목적이 같다: **승인된 시안의 재질·색을 그대로 가진
> 부품 키트.** 방식만 다르다.
>
> A안: 부위별로 크롭 → 부품마다 참조 생성 (생성 30회+)
> **B안: 화면 전체를 "빈 UI 판" 한 장으로 다시 그리고, 부품은 전부 코드가
> 잘라낸다 (생성 2장)**
>
> B안이 유리한 이유는 1차 키트에서 증명됐다: 조각을 따로 생성하면 이음
> 단면이 절대 안 맞고(절반까지 어긋남), **한 그림에서 잘라내면 오차가 0**이다.
> 색·재질 정합도 마찬가지다 — 한 장에 같이 그려진 패널들은 서로 어긋날
> 방법이 없다.

---

## 입력 — 참조 이미지 2장

| 역할 | 파일 | 이 이미지에서 가져올 것 |
| --- | --- | --- |
| **재질·색 가이드** | `KayKitHUDMockups\KK_HUD_Polish_01.png` | 나무·석재·금속·양피지의 색, 명암, 재질감. **이것과 달라 보이면 실패** |
| **구도 가이드** | 최신 검증 캡처 `Saved\UI\CombatLayouts\WBP_CombatLayout_01_ClassicCRPG.png` | 패널들의 위치·크기. 부품 절단 좌표가 이 구도 기준이므로 패널 배치는 이쪽을 따른다 |

두 참조의 역할을 섞지 말 것: **어디에 무엇이 있는지는 캡처, 어떻게 생겼는지는
시안.**

---

## 생성 1장째 — 빈 UI 판 (평시 상태)

```
ImageGen으로 그릴 것. 참조 이미지 2장을 입력으로 사용.

[그릴 것]
1920x1080. 전투 HUD의 "빈 판" 한 장.

구도 가이드(캡처)에 있는 패널들을 같은 위치·같은 크기로 전부 그리되,
재질과 색은 재질 가이드(시안)를 그대로 따른다:
- 아군 카드 3장: 어두운 호두색 나무 면 + 어두운 나무 테두리(직선은 얇게,
  모서리에만 은색 금속 브래킷과 나사)
- 스킬 카드 6장: 푸른 기 도는 석재 면 + 밝은 은색 금속 테두리
- 적 패널: 깊은 붉은 석재 면 + 금속 테두리
- 라운드/목표 현판: 양피지 면 + 나무 테두리
- 턴 종료 버튼: 주황 나무, 위로 볼록 (윗면 하이라이트 + 어두운 밑단)
- 턴 순서 토큰 5칸: 작은 나무 프레임 + 원형 금속 링
- 아군 카드 안 원형 금속 초상 링 (구멍은 배경색이 보이게)
- HP 바 홈(빈 트랙)과 채워진 바 한 토막
- 파랑 마름모 AP 보석과 꺼진 보석
- 밝은 원형 비용 배지 (숫자 없이 빈 원)

[반드시 비울 것 — 판만 필요하다]
- 글자·숫자 일절 없음 (이름, HP 수치, AP, 스킬명 전부 금지)
- 초상화 얼굴 없음 (링 구멍은 비워 둠)
- 스킬 아이콘 없음 (카드 가운데는 빈 면)
- 전장·배경 없음: 패널이 아닌 모든 픽셀은 순수 마젠타 #FF00FF

[스타일]
재질 가이드와 같은 KayKit 톤. 저폴리, 무광, 어두운 윤곽.
재질 가이드보다 채도를 올리거나 대비를 키우거나 장식을 더하지 말 것.
"더 멋지게"가 이 발주의 실패 조건이다.
```

## 생성 2장째 — 상태 변형 판

```
1장째와 완전히 같은 구도·같은 판. 상태만 바뀐다:
- 기사 카드(첫 아군 카드)와 세 번째 스킬 카드에 금색 선택 테두리
- 다섯 번째 스킬 카드에 비활성 덮개 (시안의 돌파 베기처럼 눌린 회색)
- 턴 종료 버튼은 눌린 상태 (밑단 사라지고 판이 내려앉음)

1장째와 겹쳤을 때 상태 표시 외의 픽셀이 달라지면 안 된다.
```

---

## 절단 — 내(코드) 몫

두 장을 받으면 코드가 잘라낸다. 조립 좌표는 코드가 이미 알고 있으므로
(WBP를 코드가 배치했다) **절단 좌표를 사람이 재지 않는다:**

- 나무/금속 프레임: 모서리 4 + 레일 4 → `KK_HFrame_*` `KK_MFrame_*` 규격으로
- 면 6종: 패널 안쪽에서 크롭 → 타일러블 보정 → `KK_Fill_*`
- 링·보석·배지·바: 해당 위치에서 크롭 → 기존 캔버스 규격으로
- 선택 테두리·비활성 덮개·버튼 눌림: 2장째에서 같은 방식

패널 위치가 구도 가이드와 ±16px 어긋나는 것까지는 코드가 스냅으로 흡수한다.
그 이상 어긋나면 그 장만 다시.

## 검수 — 시안 상대값 (5차-A와 동일 기준)

| 항목 | 판정 |
| --- | --- |
| 색 거리 | 각 패널 평균색 vs 시안 대응 패널, 채널당 ≤ 15 |
| 채도 거리 | ±0.08 |
| 대비 거리 | 시안의 0.7~1.4배 |
| 크로마 순도 | 마젠타 영역에 패널 픽셀 번짐 없음 (경계 안티앨리어싱 2px 허용) |
| 두 장 정합 | 1·2장째의 비상태 픽셀 차이 ≤ 채널당 8 |
| 절단 후 기하 | 기존 검사(이음 0, 타일 무결성, 알파 일치) 그대로 |

## A안과의 선택 기준

| | A 부위별 분해 | **B 스킨 원판** |
| --- | --- | --- |
| 생성 횟수 | 30회+ | **2회** |
| 부품 간 정합 | 부품마다 따로 → 어긋날 수 있음 | **한 그림이라 자동** |
| 개별 부품 품질 제어 | 부품 단위로 재발주 가능 | 판 전체를 다시 |
| 실패 시 비용 | 그 부품만 | 한 장 통째 (그래도 2장이라 쌈) |

**B를 먼저 시도하고**, 특정 부품만 계속 어긋나면 그 부품만 A 방식으로
보충하는 순서를 권한다.
