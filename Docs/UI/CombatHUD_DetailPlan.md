# 전투 HUD 디테일 마감 계획

> 전제: 배치(레이아웃)는 통과. 이제 디테일이다.
> 이 문서는 인게임 스크린샷(1600×900, 1안 오버레이)에서 **실제로 확인된 결함**에서
> 출발하고, 지금까지 확립한 작업 원칙으로 순서를 정한다.

---

## 스크린샷에서 확인된 것

**성공한 것** — 실전투 바인딩이 붙었다.
- 스킬 이름·아이콘이 게임플레이가 민 실데이터다 (베기, 강타, 검기 날리기, 방어)
- HP 100/100, 적 50/50, 라운드 표시 정상
- 명령 카드 클릭 대상이 실제 Request*() 경로에 연결된 상태

**빈 자리** — 전부 원인이 다르므로 나눠서 잡는다.

| # | 증상 | 원인 | 성격 |
| --- | --- | --- | --- |
| 1 | AP 비용 전부 "0", 피해·쿨타임 줄이 빔, 젬 0/0 | 게임플레이가 `FSkillUI`/`FUnitUI` 새 필드를 아직 안 채움 (`@TODO 게임플레이:`) | 데이터 |
| 2 | 값이 없는데 "0"이 그대로 보임 | UI가 빈 값과 0을 구분 안 함 | UI 로직 |
| 3 | 턴 순서·파티에 빈 회색 소켓 | 초상화 아트가 기사 1장뿐. 독수리 등 실제 적 초상화 없음 | 아트 |
| 4 | HP 바 끝이 각짐 | `KK_Bar_Cap` 조각을 안 씀 — ProgressBar 스타일로는 캡을 못 단다 | 부품 |
| 5 | 스킬 아이콘 톤 불일치 (강타·검기 날리기가 구 다크판타지 아트) | 게임플레이 `mIcon`이 구 아트를 가리킴 | 결정 필요 |
| 6 | 세리프 폰트가 KayKit 톤과 어긋남 | 구 아트라인 기준으로 고른 폰트 | 결정 필요 |
| 7 | 구 HUD와 겹쳐 보임 | 프리뷰 오버레이 방식 — 평가 중엔 정상, 채택 시 정리 대상 | 전환 |

## 원칙 (이번 대화에서 확립한 것)

1. **치수는 격자, 재지 않는다.** UNIT=32 하나. 안 맞으면 그림을 되돌려 보낸다.
2. **아트는 원판 → 절단.** 조각을 따로 생성하면 단면이 안 맞는다. 이어져 있는 것은
   이어진 채로 그리고 코드가 자른다.
3. **눈 검사 대신 측정.** 조립 테스트·픽셀 비교·캡처. "두께는 맞는데 무늬가 다른"
   부류는 눈이 통과시킨다.
4. **kit 하나 = 10안 동시 갱신.** 부품·팔레트 수정은 `combat_layout_kit.py`에만.
   배치안 코드는 안 건드린다.
5. **데이터는 UIModel 계약으로만.** `CombatGameMode.cpp`는 게임플레이 영역.
   요청은 PR·문서로 남기고 직접 수정하지 않는다.

## 단계

### 0단계 — 회색 퉁침 해소 (완료)

원인이 둘이었다.

1. **`fill="Stone"` 하나만 쓰였다.** Wood와 Parchment는 만들어 놓고 한 번도
   안 썼다. 10안 모든 패널이 같은 회색이었다.
2. **그 Stone이 사실상 단색이었다.** 값 범위 132~148. 1차본의 긁힌 얼룩을
   빼는 과정에서 저폴리 모자이크까지 같이 지워졌다.

처리:
- **역할별 면·색조 표**(`SURFACES`)를 두고 카드마다 다른 면을 깐다.
  아군=나무(차례인 유닛은 더 밝게) / 커맨드=석재 / 적=붉은 석재 /
  라운드·목표=양피지 / 턴 종료=주황. 형태 전에 색으로 구분된다.
- **위가 밝고 아래가 어두운 명암**을 다시 깔았다. 면 하나만으로는 판이
  납작하게 읽힌다.

그 과정에서 **프레임과 초상화 링이 통째로 안 그려지는 것**을 발견했다.
캔버스 자식 순서에만 기대고 있었는데, 카드에 부품이 늘어나자 프레임이
뒤로 밀렸다. 상단 띠(부품 적음)는 멀쩡하고 하단 카드만 사라져서 눈으로는
"아트가 안 붙었나" 로 읽혔다. 저장된 위젯을 덤프해 보니 위치·텍스처·가시성이
전부 정상이었고, 그래서 순서 문제로 좁혀졌다.

→ **그리기 층을 못 박았다**: 면 0 / 명암 1 / 내용 10 / 프레임 20 / 덮개 30 /
선택표시 40. 이제 부품이 몇 개든 층이 우연에 안 맡겨진다.

### 1단계 — 값 없는 항목 처리 (UI 로직, 바로 시작)

게임플레이 데이터를 기다리지 않고 지금 고칠 수 있는 것.

- `CombatLayoutHUDWidget`: 비용·피해·쿨타임이 **0이면 그 요소를 숨긴다.**
  지금은 "0" 배지가 그대로 떠서 미완성이 아니라 오류처럼 읽힌다.
  이동(비용 1 하드코딩)은 유지 — 계약상 이동은 항상 1이다.
- 젬 0/0일 때: 젬 줄 자체를 숨기고 자리는 유지 (레이아웃 흔들림 방지).
- 초상화가 없을 때 빈 소켓 대신 **직업/유닛 이니셜 또는 실루엣** — 소켓이
  "로딩 실패"처럼 보이는 걸 막는다.

### 2단계 — 부품 마감 (kit 수정 → 10안 동시 적용)

- **게이지 바 조립형 전환.** ProgressBar를 버리고 `Bar_Track_Cap + Track_Link +
  Cap + Link` 조각을 직접 조립하는 위젯 함수로. 끝이 둥글어지고, 채움 길이는
  격자 단위로 스냅. (지금의 "아트 높이 2배 보정" 꼼수도 같이 사라짐)
- **배지 정리.** 코스트 젬·쿨다운 배지의 위치·크기를 격자에 맞추고,
  숫자 가독성(외곽선 or 어두운 심) 확보.
- **hover/pressed 피드백.** 지금은 알파 0.10 흰 오버레이 — KayKit 톤으로
  밝아지는 정도를 키우고 pressed는 살짝 어둡게.
- **텍스트 가독성.** 이름·수치에 얇은 외곽선. 전장(밝은 초원) 위에서
  흰 글씨가 씻겨 보이는 문제.

### 3단계 — 아트 보충 (원판 방식으로 Codex ImageGen)

- **`KK_Fill_Stone` 재생성.** 지금 값 범위가 132~148뿐이라 저폴리 모자이크가
  안 남아 있다. 1차본(긁힌 얼룩)과 지금(단색) 사이를 노린다 — 큼직한 다각형
  면들이 서로 3~5% 밝기 차이. 긁힘·얼룩·붓질은 그대로 금지.

전부 **원판 → 절단 → 기계 검수** 파이프라인 재사용. 프롬프트는 기존 공통
지시(KayKit 스타일 블록 + 링 구멍 11/16 규격)를 그대로 쓴다.

- **초상화 세트**: 궁수, 마법사 + 적 (독수리/거미/슬라임 등 스테이지1 몬스터).
  게임 캐릭터(KayKit Adventurers)와 같은 톤의 정면 흉상.
- **상태이상 칩**: 중독·기절·속박 (기획서의 상태 3종부터).
- 스킬 아이콘은 5번 결정에 따름 (아래).

### 4단계 — 검증 확장 + 전환

- **캡처 매트릭스 확장**: 1920×1080 외에 1600×900, 4:3 추가. 겹침·잘림을
  자동 검출 (알파 바운딩 박스가 캔버스 밖이면 실패).
- 안 확정 후: `mHUDClass` 전환 커밋 + 구 Concept02 HUD 정리 (별도 PR).

아니라 **패널 면**이 문제였다. 아래 0단계로 처리했다.

## 순서 요약

```
지금:    1단계(UI 로직) + 2단계(부품) 병행  ← 게임플레이 안 기다림
동시에:  결정 A/B/C 받기 + 3단계 프롬프트 발주
그다음:  3단계 반입(검수 포함) → 4단계 캡처 확장
마지막:  안 확정 → 전환 커밋 + 구 HUD 정리
```
