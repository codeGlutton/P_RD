# UI 파트가 할 일 — 구조

> 작성: 박용수(UI) · 기준: 0728 회의 결정 + origin/develop 6d1ae54d
> "무엇을 만드나" 가 아니라 **어느 층에서 무엇이 막혀 있나**로 갈랐다.

---

## 0. UI 는 네 층이다

층을 섞으면 "게임플레이가 안 줘서 못 한다" 와 "내가 안 만들어서 없다" 가
구별이 안 된다. 아래는 그 넷이다.

```
① 계약      게임플레이가 UI 에 내려주는 값        FCombatUITypes / UCombatUIModel
② 굽기      WBP 를 자동으로 만드는 길             Tools/UI/*.py
③ 위젯      구운 WBP 를 읽어 그리는 C++           UCombatLayoutHUDWidget 등
④ 도구·문서 자리를 맞추고 시안을 요청하는 것       zones.html · Docs/Design
```

**막히는 곳은 거의 ①이다.** ②③④ 는 내 손 안에 있다.

---

## 1. 지금 당장 할 수 있는 것 — 값이 이미 있다

### 1.1 develop 머지 ★ 가장 먼저

develop 에 **파티 리팩토링이 들어왔다**(PR #445). 내 브랜치는 그 이전 기준이라
지금 합치지 않으면 나중에 충돌이 커진다.

| 겹치는 곳 | 어떻게 |
|---|---|
| `PersistentData.h` | **내 것을 버린다.** 저쪽이 `UPartyModel` + 아티팩트까지 나갔다 |
| `CombatGameMode.cpp` | 109줄 바뀜. 내 파티 코드를 걷어내고 저쪽 것에 맞춘다 |
| `FUnitUI` 배열 · 아군 칸 셋 | **그대로 쓴다.** 게임플레이가 값을 내려주므로 UI 는 안 바뀐다 |

> 돈이 파티 공용으로 정해졌다 -- `LevelAttributeSet` 에서 `Money` 를 빼고
> `PartyAttributeSet` 에 넣었다. 인벤토리 기획의 열린 질문 하나가 닫혔다.

### 1.2 AP 표기를 `@ × n` 으로

회의 결정. 값(`Movement`)은 이미 온다.

- `AP_PIPS = 8` 과 `PartyAPPip_0~7` 여덟 개를 지운다
- `PartyAPIcon` + `PartyAPText` 한 벌만 남긴다
- 아군 칸의 `ap_gems` 구역(160×27)을 그 크기로 줄인다
- 전투_기획 3장의 "여덟까지 낱개" 문장을 지운다

### 1.3 `BP/UI` → `UI` 폴더 정리

`Content/BP/UI` 에 옛 WBP 여섯 장이 남아 있다. 참조가 걸려 있으니 옮기고
빌드·시험을 돌린다.

### 1.4 문서 세 개 고치기

| 문서 | 무엇이 틀렸나 |
|---|---|
| `전투_기획_시안4.md` | "여덟까지 낱개" · "피해는 주사위?" · "방어는 뺄셈인가" |
| `상세창_표시항목.md` | "크리티컬은 안 적는다" → 확률이 유닛마다 다르면 용병 창엔 적어야 |
| `시안4_3_요청서.md` | "피해는 한 숫자" → **min~max 로 되돌아감** |

**방어는 이미 답이 나와 있다** — 뺄셈도 비율도 아니고 소모되는 실드다.

## 2. 계약이 먼저인 것 — 게임플레이가 값을 줘야 한다

### 2.1 피해 min~max · 크리티컬

**UI 는 준비돼 있다.** `FSkillUI` 에 `mDamageMin` `mDamageMax` `mCriticalDamage`
가 이미 있다. 채우는 쪽만 생기면 그날 바로 그린다.

**부탁할 것 (모호재님)**

- `FSkillEffectLayer_Attack` 에 min/max
- 자동 생성 설명이 `8~12` 로 바뀌면 스킬 상세창 글이 그대로 따라온다

**부탁할 것 (크리티컬 확률)**

- `CriticalChance` 능력치. 지금 `CombatTargetAttributeSet` 에 **없다**
- 유닛마다 다르므로 **용병 상세창에 한 줄**이 필요하다
- 스킬 상세창에는 안 적는다 -- 배율이 고정이고 확률은 유닛 것이라 스킬마다
  적으면 같은 말이 여섯 번 반복된다

### 2.2 적 다음 행동 미리보기

회의에서 정한 것 중 **UI 일이 가장 많은 것**이다. 계약이 아예 없다.

```cpp
USTRUCT(BlueprintType)
struct FEnemyIntentUI
{
    int32              mUnitId;
    FText              mSkillName;      // 다음에 쓸 스킬
    UTexture2D*        mSkillIcon;
    int32              mDamageMin;
    int32              mDamageMax;
    TArray<FTileIndex> mThreatTiles;    // 칠할 칸
};
```

**`mThreatTiles` 를 게임플레이가 계산해 내려줘야 한다.** UI 가 사거리를 다시
세면 AI 판정과 어긋나는 날이 온다 -- 카드 켜고 끄는 것도 그래서 게임플레이에
맡겼다.

**UI 가 할 일**

- 적 정보창에 **다음 스킬 하나** 표시 (회의 결정)
- 판에 위협 칸 칠하기. `SRPGSkillBuildAction` 의 하이라이트와 같은 길을 쓴다
- 플레이어가 움직이면 다시 그린다

### 2.3 "적이 AP 가 모자라 못 때린다"

호재님이 짚은 것. **위협 칸을 안 칠하는 것**으로 푸는 게 가장 조용하다 --
칠할 게 없으면 그 턴은 안 온다는 뜻이 된다. 적 정보창에 AP 를 같이 두면 왜
그런지도 읽힌다(`Movement` 로 값은 이미 있다).

### 2.4 상태이상 남은 턴

`FStatusEffectUI` 에 `mTag` + `mStackCount` 뿐이다. **남은 턴이 없다.**
지금 그릴 수 있는 것은 `×2` 같은 중첩 수뿐이다.

전투_기획에 "상태이상에 남은 턴이 붙는다" 고 적어 둔 것은 **틀렸다.**

## 3. 물건이 아직 없는 것

### 3.1 기믹(장판·가시박스)

회의에서 "기믹에도 피해와 크리티컬" 로 정했는데, **`Trap`·`Hazard` 같은 것이
코드에 하나도 없다.** 이야기만 있고 물건이 없으므로 UI 로 할 일이 없다.

정해지면 그때 상세창을 붙인다.

### 3.2 빔 관통/비관통 분리

지금은 `EEffectPattern.Beam` 하나 + `mIsPenetration` 조합이다. 나누기로 하면
사거리 도해의 색이 갈린다. **둘 다 UI 는 되므로 게임플레이가 정하는 대로 따른다.**

## 4. 내 손 안에서 굴러가는 것

### 4.1 전투 HUD 굽기 — 돌아간다

```
시안4 측정  →  맞춘 값 덮기  →  빈 자리 메우기  →  hud04_slots.py  →  WBP
              (hud04_tuning)                        build_hud04.py
```

곁들여 붙은 것: 구역 그림·판 그림·글자 붙임·층을 쪽에서 정하고 내보내면
그대로 구워진다.

**확인하는 눈도 있다** -- `check_hud04.py` 가 구운 WBP 를 열어 카드마다 판
그림과 자리를 적어 낸다. 코드를 읽고 "같다" 고 말하는 것과 나온 것이 그런
것은 다른 이야기라, 세 번 틀린 뒤에 만들었다.

### 4.2 아직 안 그리는 구역

| 구역 | 왜 |
|---|---|
| `status_icon_1~4` | 런타임이 아군 칸마다 상태 아이콘 **하나**만 안다. 다섯을 살리려면 `PartyStatusIcon_<아군>_<칸>` 으로 이름을 두 겹으로 바꾸고 C++ 도 손봐야 한다 |

## 5. 순서 제안

**값이 없어도 되는 것부터.** 남을 기다리는 일이 줄어든다.

1. **develop 머지** — 미룰수록 비싸진다
2. **AP 표기 `@ × n`** — 값이 이미 있다
3. **`BP/UI` → `UI` 폴더**
4. **문서 셋 고치기** — 팀이 틀린 문서를 보고 있다
5. **글자 규칙 확정** (크기 다섯·색 넷·숫자 형식) — 인벤/상점/지도가 다 이걸 기다린다
6. **상세창 시안 재요청** — 피해 min~max 가 확정된 뒤
7. **적 다음 행동** — 계약이 생긴 뒤
8. **인벤토리 → 상점 → 스킬탭 → 지도** — 5번이 끝난 뒤
