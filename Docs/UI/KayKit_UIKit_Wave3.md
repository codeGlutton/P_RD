# KayKit UI 키트 3차 — 코드로는 못 메우는 마감 격차

목업과 구현을 나란히 놓고 디자이너 관점으로 뜯은 결과, 격차가 세 부류로 갈렸다.

1. **캡처 왜곡** — 감마 설정. 고쳤다.
2. **코드로 되는 것** — 폰트·그룹핑·색 코딩·배지 대비·림 라이트·드롭섀도. 했다.
3. **아트가 없어서 안 되는 것** ← 이 문서

3번만 남았다. 아래는 전부 **실측 근거**가 있는 것들이다. 취향으로 고른 게 아니다.

1차 41조각 · 2차 16조각의 규약을 그대로 따른다 — 격자 1U = 32px, 그림은 4배,
투명 PNG, 정투영 정면, 조각 바깥 픽셀은 완전 투명.

**생성 방식은 1차에서 검증된 원판 절단이다.** 조각을 따로 뽑으면 이음 단면이
절대 안 맞는다(1차에서 절반까지 어긋났고, 원판으로 바꾸자 오차 0이 됐다).
완성된 판을 한 장 그리고 격자 경계에서 코드가 잘라낸다.

---

## 왜 이것들인가 — 실측

| 항목 | 목업 | 구현 | 측정 |
| --- | --- | --- | --- |
| 스킬 카드 테두리 | **회색 금속** | 나무 | 나무 한 종뿐. 나무에 회색을 곱하면 흙탕이 된다 |
| 아이콘 밝기 | 밝은 황갈 | 진한 적갈 | `KK_Icon_Move` 불투명 평균 밝기 **93**. 목업은 ~190 |
| 버튼 | 볼록, 밑단 그림자 | 평면 | 정보 판과 버튼이 같은 문법. 누를 수 있는 것이 형태로 안 갈림 |
| 리벳 | 코너 4개 + 드문드문 | 이음마다 1개 | 이음 조각에 박혀 있어 작은 카드일수록 시끄러워지는 구조 |
| 파티 AP 보석 | **파랑** | 금색 | 금색에 파랑을 곱하면 검어진다. 틴트로 못 감 |

## A. 금속 프레임 원판 2장

스킬 카드·적 패널은 금속, 아군 카드는 나무다. 지금은 전 패널이 같은 나무
테두리라 **역할 구분이 프레임에서 안 일어난다.**

### A-1 두꺼운 금속 프레임 원판

```
[그릴 것]
완성된 UI 패널 한 장. 안은 비어 있고 테두리만 있다.

굵게 깎인 회색 금속 테두리(#9AA0A9, 밝은 면 #C3C7CE, 그늘 #6E747E)가
사각형을 두른다. 모서리에는 조금 더 두꺼운 금속 코너 블록이 덧대어져 있고
거기에만 둥근 리벳 두 개씩.

**직선 구간에는 리벳도 장식도 없다.** 단면이 처음부터 끝까지 같은,
매끈하게 깎인 금속 몰딩이다.

네 변의 몰딩은 완전히 같은 단면이다. 위/아래/좌/우가 같은 굵기, 같은
모따기, 같은 색이다. 빛만 위에서 와서 위쪽이 밝고 아래쪽이 어둡다.
어느 한 변에만 있는 장식은 절대 금지다.

[치수]
캔버스 1024x768, 투명 배경. 패널 테두리는 캔버스를 꽉 채운다.
테두리 띠 두께는 정확히 128px.
모서리 코너 블록은 각 구석 256x256px 안에서 끝난다.
안쪽(테두리를 뺀 가운데)은 완전히 투명하다.
```

### A-2 얇은 금속 프레임 원판

같은 지시, 캔버스 512x384, 띠 두께 64px, 모서리 128x128.
장식은 더 단순하게 — 코너 블록에 리벳 하나씩.

**자를 것**: 각 원판에서 `Corner_T` / `Corner_B` / `Link_T` / `Link_B` / `Link_S`
(1차 `KK_HFrame_*` · `KK_LFrame_*`와 같은 좌표). 파일명은
`KK_MFrame_*` / `KK_MLFrame_*`.

## B. 나무 프레임 원판 재생성 (리벳 제거)

1차 나무 원판은 직선 구간에도 리벳이 박혀 있다. 그래서 작은 카드에서 이음이
반복될수록 리벳이 8개씩 늘어선다. 목업은 코너에만 있다.

```
A-1과 같은 지시, 재질만 나무(#8B5E3C, 깎인 면 #A9653F).
모서리에 금속 코너 브래킷 + 리벳 두 개씩.
**직선 구간에는 리벳 없음.** 단면이 일정한 나무 몰딩.

캔버스 1024x768(두꺼운) / 512x384(얇은), 띠 두께 128px / 64px.
```

리벳을 드문드문 넣고 싶으면 코드가 `KK_Rivet`(1차 F6)을 원하는 간격으로
얹는다. 조각에 박아 두면 간격을 못 고른다.

## C. 볼록 버튼 원판 2장 (평시 · 눌림)

지금 턴 종료 버튼은 정보 패널과 **같은 문법**이라 누를 수 있는 것으로 안
읽힌다. 목업의 버튼은 위 하이라이트 + 아래 진한 밑단으로 볼록하다.

### C-1 평시

```
[그릴 것]
누를 수 있는 버튼 한 개. 위로 볼록하다.

주황 나무판(#A9653F, 윗면 밝은 #C87A4A)이고, 판 아래쪽에 한 단 더 진한
밑단(#7A4529)이 4~6px 두께로 깔려 "떠 있는 판"처럼 보인다.
윗면 상단 가장자리에 밝은 림 라이트 한 줄.
테두리는 얇은 금속 선(#9AA0A9). 안쪽은 균일하다.

[치수]
캔버스 1024x256, 투명 배경. 버튼은 캔버스를 꽉 채운다.
모서리 곡률은 각 구석 128x128px 안에서 끝난다.
변의 가운데 구간은 늘려도 어색하지 않도록 무늬 없이 균일해야 한다.
```

### C-2 눌림

```
C-1과 완전히 같은 크기·같은 색. 눌린 상태다.
밑단이 사라지고 판 전체가 아래로 4~6px 내려앉는다.
윗면 림 라이트가 사라지고 대신 상단 안쪽에 얕은 그늘이 진다.

두 장을 겹쳐 놨을 때 바깥 실루엣이 1px도 어긋나면 안 된다.
같은 버튼을 두 상태로 두 번 렌더하는 것이다.
캔버스 1024x256.
```

**자를 것**: `KK_Button_Corner` / `KK_Button_Link_H` / `KK_Button_Link_V`,
평시와 눌림 각각. 파일명 접미사 `_Up` / `_Down`.

## D. 아이콘 8종 재생성 (밝게)

1차 아이콘이 KayKit 톤보다 한참 어둡게 나왔다. `KK_Icon_Move`의 불투명 픽셀
평균 밝기가 **93**이다. 목업의 같은 부츠는 ~190이다.

```
[추가 지시 — 이번에 틀린 부분]
1차 결과물이 전체적으로 너무 어둡고 채도가 낮았다. 진한 적갈색 덩어리로
보여서, 밝은 카드 위에 얹으면 구멍처럼 읽힌다.

물체의 본색을 밝게 잡을 것. 가죽은 진한 고동색이 아니라 밝은 황갈색,
금속은 짙은 회색이 아니라 밝은 은색이다. 빛을 받는 면은 팔레트에서
가장 밝은 값에 가깝게 올린다.

불투명 픽셀의 평균 밝기가 160 이상이어야 한다.
그늘은 형태를 만들 만큼만 주고, 물체 전체를 어둡게 덮지 말 것.
```

| 파일 | 그릴 것 |
| --- | --- |
| `KK_Icon_Move` | 밝은 황갈색 가죽 부츠 한 짝 |
| `KK_Icon_BasicAttack` | 밝은 은색 검 두 자루가 X자로 교차 |
| `KK_Icon_ShieldBash` | 흰·빨강 방패가 앞으로 밀려 나오는 모습 |
| `KK_Icon_PinSlash` | 밝은 은색 검 한 자루가 아래로 꽂힌 모습 |
| `KK_Icon_Breakthrough` | 방패가 쪼개지고 그 사이로 밝은 검이 지나간 모습 |
| `KK_Icon_Riposte` | 방패를 세우고 검을 뒤로 당긴 방어 자세 |
| `KK_Icon_EndTurn` | 나무틀 모래시계, 밝은 나무 + 크림색 모래 |
| `KK_Icon_Objective` | 빨간 깃발, 밝은 나무 깃대 |

캔버스 256x256, 물체는 가운데 192x192 안. 바닥 그림자 금지.

## E. 파랑 AP 보석 2종

목업의 아군 AP 보석은 파랑이다. 지금 아트는 금색이고, **금색에 파랑 틴트를
곱하면 검어진다** — 색 변환으로는 도달할 수 없다.

```
[그릴 것 — KK_Gem_Blue_On / KK_Gem_Blue_Off]
행동력 한 칸을 나타내는 마름모 보석.
On: 밝은 파랑 #4A82C8, 위쪽 면에 넓은 하이라이트, 안이 차 있다.
Off: 완전히 같은 실루엣·같은 위치, 색만 회색 #6E747E로 꺼져 있고
     안이 비어 보인다.

1차 KK_Gem_On / KK_Gem_Off와 **알파가 완전히 같아야 한다.** 같은 형태를
색만 바꿔 렌더하는 것이다.
캔버스 128x128, 보석은 가운데 96x96 안.
```

금색은 커맨드 카드의 비용 배지에 계속 쓰므로 **1차 금색 보석은 남긴다.**
아군은 파랑, 비용은 금색으로 갈라진다.

## 검수 — 이번에 추가할 항목

1·2차 검수(캔버스 크기·이음 단면·타일 이음매·안전 여백·팔레트)에 더한다.

| 새 항목 | 방법 | 왜 |
| --- | --- | --- |
| **아이콘 밝기 하한** | 불투명 픽셀 평균 밝기 ≥ 160 | 1차가 93으로 나왔고, 눈으로는 "좀 어둡네" 정도로만 보여서 통과시켰다 |
| **직선 구간 리벳 없음** | 잘라 낸 Link 조각의 국소 대비 상위 1%가 임계 이하 | 리벳이 박혀 있으면 여기서 걸린다 |
| **버튼 두 상태 실루엣 일치** | `_Up` / `_Down` 알파 마스크 차이 ≤ 64픽셀 | 어긋나면 누를 때 버튼이 튄다 |
| **파랑 보석 알파 일치** | 금색 보석과 알파 마스크 동일 | 두 색을 같은 자리에 갈아 끼울 수 있어야 한다 |
| **금속 vs 나무 단면 두께 일치** | 두 프레임의 Link 조각 이음면 두께가 서로 ±2px | 같은 카드에서 섞어 쓰지는 않지만, 다르면 배치 코드가 두 벌이 된다 |

**한 항목이라도 틀리면 그 원판만 다시 뽑는다.** 그림에 코드를 맞추지 않는다.

## 이 키트가 들어오면 코드에서 바뀌는 것

`combat_layout_kit.py`의 `SURFACES` 옆에 `FRAMES` 표가 하나 생긴다.

```
아군·정보 → 나무 프레임
스킬·적·턴  → 금속 프레임
버튼        → 볼록 버튼 프레임 (평시/눌림)
```

`frame()`은 이미 `weight` 딕셔너리로 조각 접두사를 받으므로 **접두사만 늘리면
된다.** 배치안 열 개는 손대지 않는다.
