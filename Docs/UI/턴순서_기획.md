# 턴 순서 줄 — 여섯을 기준으로

> 작성: 박용수(UI) · 근거: `SRPGCombatModel` · `hud04_slots` · 방 데이터에셋 열 개를 직접 읽은 것

---

## 0. 두 줄

- **여섯이 맞는 수다.** 아군 셋 + 지금 방 데이터의 적 최대 셋 = 정확히 여섯
- **넘칠 때는 여섯째 칸을 `+N` 으로 바꾼다.** 자리를 안 늘리고 몇인지 늘 보인다

---

## 1. 지금 무엇이 어긋나 있나

| | 값 |
|---|---|
| C++ 이 찾는 칸 | **여섯** (`TurnSlotCount = 6`) |
| 판 그림에 그려진 칸 | **다섯** |
| 게임플레이가 내려주는 수 | **전부** (`mTurnOrderUnitIds` 는 안 자른다) |

**셋이 다 다르다.** 그래서 여섯째부터는 값이 왔는데 그릴 자리가 없어 **말없이
잘린다.** 잘렸다는 표시도 없다.

순서는 **스폰 순서 그대로**이고 다시 안 섞인다 -- 아군을 먼저 다 넣고
(`InitCombat`) 그다음 방 데이터에 적힌 순서로 적을 넣는다. 속도 능력치 같은
것은 없다.

---

## 2. 왜 여섯인가

방 데이터에셋 열 개를 다 열어 본 값이다.

| 방 | 적 |
|---|---|
| `DA_TestMonster2_Stage1` · `DA_TestMonster_Stage3` | **3** |
| `DA_TestMonster_Stage1` · `_Stage2` | 2 |
| `DA_TestBoss_Stage1` · `DA_TestElite_Stage1` | 1 |
| 나머지 넷 | 0 (아직 안 채움) |

**가장 많은 방이 셋이다.** 파티가 셋(`DefaultPartySize`)이므로 여섯이 상한이다.

---

## 3. 여섯을 넘는 경우 — 넷

지금 코드에서 실제로 일어날 수 있는 것만 적는다.

| 무엇 | 지금 | 막는 것이 있나 |
|---|---|---|
| **방에 적을 넷 이상 넣는다** | 안 넣었을 뿐 | **없다.** 배열이라 몇이든 들어간다 |
| **한 유닛에 턴을 더 준다** | 안 쓰임 | 없다. `RegisterTurn(Owner, LifeCount)` 가 이미 됨 |
| **파티가 넷 이상** | 셋 고정 | `DefaultPartySize` 한 줄 |
| **소환** | 개념 없음 | 효과 레이어에 소환이 없다 |

**둘째가 재미있다.** 같은 유닛이 고리에 두 번 들어가므로 줄에도 **두 번 뜬다.**
그게 맞다 -- "이 적이 이번 라운드에 두 번 움직인다" 를 그대로 보여 준다.
지금 코드도 그렇게 그린다(칸 번호로 세지 유닛으로 안 센다).

**보스 방이 위험하다.** 보스 하나 + 졸개 넷이면 아군 셋과 합쳐 여덟이다.

---

## 4. 정한 것 — 여섯 칸 + 꼬리표

```
 N ≤ 6      [초상][초상][초상][초상][초상][초상]
 N > 6      [초상][초상][초상][초상][초상][ +3 ]
              지금   다음   ...              나머지 수
```

**여섯째 칸이 두 얼굴을 가진다.** 여섯 이하면 그냥 여섯째 유닛, 넘치면 남은
수를 적는 꼬리표가 된다. 칸을 하나 더 만들지 않는 것은 판 그림을 또 늘려야
하기 때문이다.

### 왜 옆으로 미는 방식을 안 쓰나

**모바일이라 그렇다.** 전투 중에 UI 를 굴리게 만들면 두 번 만질 것을 세 번
만진다. 그리고 **안 보이는 것은 없는 것**이라, 굴려야 보이는 정보는 아무도
안 본다.

### 왜 칸을 줄여 여덟을 안 넣나

초상이 작아지면 누가 누군지 안 보인다. 지금 85픽셀도 큰 편이 아니다.
그리고 여덟로 늘려도 아홉이 오면 또 막힌다 -- 꼬리표는 몇이든 받는다.

### 꼬리표를 누르면 전체 목록이 뜨게 하나

**지금은 안 한다.** 순서가 스폰 순서 그대로라 첫 라운드에 한 번 외우면 끝이다.
매 라운드 다시 볼 이유가 없다.

> **순서를 능력치로 정하기로 바뀌면 이 판단이 뒤집힌다.** 그때는 매 라운드
> 순서가 달라지므로 전체 목록을 볼 길이 필요하다. 그 결정이 먼저다.

---

## 5. 죽으면

고리에서 빠지므로 **줄이 저절로 줄어든다.** 여섯이 다섯이 되고, 넘치던
꼬리표는 남은 수가 0이 되면 여섯째 유닛 얼굴로 돌아온다.

따로 할 일이 없다. `PushTurnUIData` 가 남은 것만 내려준다.

## 6. 판 그림 — 새로 받아야 한다

지금 판(`KK_HUD04_top_center_turn_order`)에는 **칸 다섯이 그림 안에 그려져
있다.** 여섯으로 늘리려면 그림을 다시 받는 수밖에 없다.

### 잰 값

| | 지금 | 부탁할 것 |
|---|---|---|
| 판 크기 | 713 × 158 | **808 × 158** |
| 화면 자리 | (483, 12) | **(432, 12)** |
| 칸 수 | 5 | **6** |
| 칸 크기 | 85 × 85 | 그대로 85 × 85 |
| 칸 간격 | 122.5 | 그대로 122.5 |
| 첫 칸 (판 안) | 70, 37 | **55, 37** |

**칸 크기와 간격은 안 바꾼다.** 초상과 금테두리가 그 크기에 맞춰져 있어서,
바꾸면 얹은 것을 전부 다시 맞춰야 한다.

### 자리가 있나 — 있다

```
0        324        432                1240   1271        1672
|  ROUND  |          |   턴 순서 808    |      |  메뉴 막대  |
                 108칸                    31칸
```

라운드 판이 324 에서 끝나고 메뉴 막대가 1271 에서 시작한다. **808 을 가운데
놓으면 양옆이 108 과 31 로 남는다.** 오른쪽이 좁지만 겹치지 않는다.

돌다가, 그림이 오면 여섯 + 꼬리표가 된다 -- 칸 수를 세어 돌기 때문에 코드는
안 바뀐다.

---

## 8. 확인 부탁

- **여섯이 맞나.** 보스 방에 졸개를 몇까지 둘 생각인가 — 넷이면 여덟이 된다
- **한 유닛에 턴을 두 번 주는 것을 쓸 계획인가** (`LifeCount` 는 이미 됨)
- **순서를 능력치로 정할 것인가** — 그러면 꼬리표 대신 전체 목록이 필요하다
