# 턴 순서 줄 — 여섯을 기준으로

> 작성: 박용수(UI) · 근거: `SRPGCombatModel` · `hud04_slots` · 방 데이터에셋 열 개를 직접 읽은 것
> 고침: 미끄러지는 안을 버리고 **줄어드는 줄**로 되돌림

---

## 0. 세 줄

- **끝난 차례는 앞에서 빠진다.** 강조는 늘 첫 칸이다 — 지금 코드가 그렇다
- **여섯이 맞는 수다.** 아군 셋 + 지금 방 데이터의 적 최대 셋
- **넘치면 여섯째 칸을 `+N` 꼬리표로 바꾼다**

---

## 1. 미끄러지는 안을 왜 버렸나

한 번 "목록은 고정, 강조만 이동" 으로 짜 봤는데 **틀렸다.**

턴 순서 줄이 답해야 하는 질문은 **"다음이 누구냐"** 하나다. 지나간 차례는
답에 안 들어간다. 강조를 옮기면 이미 끝난 얼굴들이 왼쪽에 계속 쌓여, 정작
봐야 하는 다음 차례가 오른쪽으로 밀린다.

**앞에서 빠지면 늘 첫 칸이 지금이고 둘째 칸이 다음이다.** 눈이 갈 자리가
고정된다.

---

## 2. 지금 코드가 이미 그렇다

`GetOrderedTurnContexts()` 는 **지금 차례부터** 고리를 한 바퀴 돈다.

```
기사 차례   [기사][야만][마법][적1][적2][적3]
야만 차례   [야만][마법][적1][적2][적3][기사]
마법 차례   [마법][적1][적2][적3][기사][야만]
```

**끝난 것은 앞에서 빠지고 꼬리에 다시 붙는다.** 고리라서 그렇다 -- 꼬리에
붙은 기사는 "다음 라운드의 기사" 다.

그래서 줄은 **늘 여섯 칸**이다. 라운드가 끝나 가도 빈칸이 안 생긴다.

### 여기서 갈리는 것 하나

| | 어떻게 보이나 | |
|---|---|---|
| **A. 고리 그대로 (지금)** | 늘 여섯. 꼬리에 다음 라운드가 붙어 보임 | **권장** |
| B. 이번 라운드만 | 여섯 → 다섯 → … → 하나. 라운드 끝이 또렷 | 줄이 쪼그라듦 |

**A 를 권한다.** B 는 라운드 끝에 얼굴 하나만 덩그러니 남고, 그때가 하필
"다음 라운드에 누가 먼저냐" 가 가장 궁금한 순간이다.

A 의 약점은 **어디서 라운드가 바뀌는지 안 보인다**는 것이다. 칸 사이에 금 하나를
넣으면 풀린다 -- 판 그림에 세로 선 한 줄이면 된다. 급하지 않다.

> B 로 가려면 `PushTurnUIData` 에서 고리를 한 바퀴 다 돌지 말고 머리에
> 닿으면 멈추면 된다. **한 줄이다.**

---

## 3. 왜 여섯인가

방 데이터에셋 열 개를 다 열어 본 값이다.

| 방 | 적 |
|---|---|
| `DA_TestMonster2_Stage1` · `DA_TestMonster_Stage3` | **3** |
| `DA_TestMonster_Stage1` · `_Stage2` | 2 |
| `DA_TestBoss_Stage1` · `DA_TestElite_Stage1` | 1 |
| 나머지 넷 | 0 (아직 안 채움) |

파티가 셋(`DefaultPartySize`)이므로 **셋 + 셋 = 여섯**이 상한이다.

---

## 4. 지금 어긋나 있는 것

| | 값 |
|---|---|
| C++ 이 찾는 칸 | **여섯** (`TurnSlotCount = 6`) |
| 판 그림에 그려진 칸 | **다섯** |
| 게임플레이가 내려주는 수 | **전부** (안 자른다) |

**셋이 다 다르다.** 여섯째부터는 값이 왔는데 그릴 자리가 없어 **말없이 잘린다.**
잘렸다는 표시도 없다.

---

## 5. 여섯을 넘는 경우 — 넷

| 무엇 | 막는 것이 있나 |
|---|---|
| **방에 적을 넷 이상 넣는다** | **없다.** 배열이라 몇이든 들어간다 |
| **한 유닛에 턴을 더 준다** | 없다. `RegisterTurn(Owner, LifeCount)` 가 이미 됨 |
| 파티가 넷 이상 | `DefaultPartySize` 한 줄 |
| 소환 | 효과 레이어에 소환이 없다 |

둘째는 같은 유닛이 줄에 **두 번 뜬다.** 그게 맞다 -- "이 적이 이번 라운드에
두 번 움직인다" 를 그대로 보여 준다. 지금 코드도 칸 번호로 세지 유닛으로 안
센다.

**보스 방이 위험하다.** 보스 하나 + 졸개 넷이면 여덟이다.

---

## 6. 넘칠 때 — 여섯째 칸이 두 얼굴

```
 N ≤ 6      [지금][다음][ 3 ][ 4 ][ 5 ][ 6 ]
 N > 6      [지금][다음][ 3 ][ 4 ][ 5 ][ +3 ]
```

여섯 이하면 여섯째 유닛, 넘치면 남은 수를 적는 꼬리표가 된다. 칸을 하나 더
만들지 않는 것은 판 그림을 또 늘려야 하기 때문이다.

**꼬리표는 안 눌린다.** 버튼을 안 얹는다 -- 눌리는데 아무 일도 안 일어나면
고장으로 읽힌다.

### 왜 옆으로 미는 방식을 안 쓰나

**모바일이라 그렇다.** 전투 중에 UI 를 굴리게 만들면 두 번 만질 것을 세 번
만진다. 그리고 굴려야 보이는 정보는 아무도 안 본다.

### 왜 칸을 줄여 여덟을 안 넣나

초상이 작아지면 누가 누군지 안 보인다. 여덟로 늘려도 아홉이 오면 또 막힌다 --
꼬리표는 몇이든 받는다.

---

## 7. 죽으면

고리에서 빠지므로 **줄이 저절로 줄어든다.** 넘치던 꼬리표는 남은 수가 0이
되면 여섯째 얼굴로 돌아온다. 따로 할 일이 없다.

---

## 8. 판 그림 — 새로 받아야 한다

칸 다섯이 **그림 안에** 그려져 있다.

| | 지금 | 부탁할 것 |
|---|---|---|
| 판 크기 | 713 × 158 | **808 × 158** |
| 화면 자리 | (483, 12) | **(432, 12)** |
| 칸 수 | 5 | **6** |
| 칸 크기 | 85 × 85 | 그대로 |
| 칸 간격 | 122.5 | 그대로 |
| 첫 칸 (판 안) | 70, 37 | **55, 37** |

**칸 크기와 간격은 안 바꾼다.** 초상과 금테두리가 그 크기에 맞춰져 있어, 바꾸면
얹은 것을 전부 다시 맞춰야 한다.

```
0      324    432            1240  1271      1672
|ROUND |      |  턴 순서 808   |     | 메뉴 막대 |
          108칸                 31칸
```

라운드 판과 메뉴 막대 사이에 들어간다.

## 10. 확인 부탁

- **A 냐 B 냐** (2장) — 꼬리에 다음 라운드를 보여 주나, 이번 라운드만 보여 주나
- **보스 방에 졸개를 몇까지** 두나 — 넷이면 여덟이 된다
- **한 유닛에 턴을 두 번** 주는 것을 쓸 계획인가
