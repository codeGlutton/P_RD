# 턴 순서 줄 — 여섯 칸 + 양끝 넘김칸

> 작성: 박용수(UI) · 근거: `SRPGCombatModel` · `hud04_slots` · 방 데이터에셋 열 개를 직접 읽은 것
> 고침 3: 양끝에 넘김칸을 두는 방식으로 확정

---

## 0. 세 줄

- **가운데 여섯 칸 + 양끝 넘김칸 둘.** 모두 여덟 자리
- **넘김칸은 그쪽에 가려진 수**를 적는다. 없으면 빈칸
- **누르면 그쪽으로 창이 옮겨 간다** — 그 판에 도는 애들을 다 볼 수 있다

---

## 1. 그려지는 모습

여섯 이하 — 넘김칸 둘 다 빈칸.

```
[  ][기사][야만][마법][적1][적2][적3][  ]
```

일곱 — 오른쪽에 하나 가려졌다.

```
[  ][기사][야만][마법][적1][적2][적3][+1]
```

`+1` 을 누르면 창이 오른쪽 끝으로 간다. 이제 왼쪽에 하나 가려졌다.

```
[+1][야만][마법][적1][적2][적3][적4][  ]
```

`+1` 을 다시 누르면 처음으로 돌아온다.

**넘김칸은 화살표가 아니라 수다.** "저쪽에 몇 남았나" 를 그대로 적으므로,
누르지 않고도 이번 판에 몇이 도는지 알 수 있다.

---

## 2. 규칙

| | |
|---|---|
| 창 크기 | 여섯 고정 |
| 창 시작 | 기본 0. **차례가 바뀌면 0으로 되돌린다** |
| 왼쪽 넘김칸 | `창 시작` 이 0보다 크면 그 수. 누르면 **0으로** |
| 오른쪽 넘김칸 | `전체 - (창 시작 + 6)` 이 0보다 크면 그 수. 누르면 **끝으로** |

**한 번 누르면 저쪽 끝까지 간다.** 한 칸씩 밀면 일곱에서 여덟 번을 눌러야
하는 판이 생긴다. 여섯 칸 창에서 볼 것이 그렇게 많지 않다.

차례가 바뀌면 되돌리는 것은, 줄 자체가 한 칸 밀리기 때문이다. 옮겨 둔 창을
그대로 두면 다음 턴에 엉뚱한 곳을 보고 있다.

---

## 3. 판 그림 — 새로 받아야 한다

칸 다섯이 **그림 안에** 그려져 있다.

| | 지금 | 부탁할 것 |
|---|---|---|
| 판 크기 | 713 × 158 | **819 × 158** |
| 화면 자리 | (483, 12) | **(426, 12)** |
| 초상 칸 | 5 | **6** |
| 초상 크기 | 85 × 85 | 그대로 |
| 초상 간격 | 122.5 | **108** |
| 넘김칸 | 없음 | **양끝에 50 × 55 하나씩** |

**초상 크기는 안 바꾼다.** 얹은 초상과 금테두리가 그 크기에 맞춰져 있다.
간격만 122.5에서 108로 좁혀 여덟 자리를 만든다.

### 자리 (판 왼쪽 위가 원점)

```
end_left          ( 24, 52,  50, 55)
turn_portrait_01  ( 97, 37,  85, 85)
turn_portrait_02  (205, 37,  85, 85)
turn_portrait_03  (313, 37,  85, 85)
turn_portrait_04  (421, 37,  85, 85)
turn_portrait_05  (529, 37,  85, 85)
turn_portrait_06  (637, 37,  85, 85)
end_right         (745, 52,  50, 55)
```

### 화면에 들어가나 — 들어간다

```
0      324    426                    1245 1271     1672
|ROUND |      |     턴 순서 819       |    |메뉴 막대|
          102칸                        26칸
```

라운드 판이 324 에서 끝나고 메뉴 막대가 1271 에서 시작한다. 화면 가운데(836)에
맞추면 양옆이 102 와 26 으로 남는다. **오른쪽이 좁지만 겹치지 않는다.**

### 넘김칸 생김새

**초상 칸과 달라 보여야 한다.** 얼굴이 들어가는 자리가 아니라 수가 들어가는
자리다. 안쪽을 파거나 색을 죽인 작은 홈이면 된다 -- 빈칸일 때가 대부분이므로,
비어 있어도 판이 어색하지 않아야 한다.

---

## 4. 라운드 경계는 어떻게 하나 — 아직 안 정함

줄이 고리를 도는 한, 어딘가에서 이번 라운드가 끝나고 다음이 시작된다.

지금 안에서는 **넘김칸이 그 답을 대신 못 한다.** 넘김칸은 "가려진 수" 지
"라운드 경계" 가 아니다.

두 갈래다.

| | 어떻게 | 값 |
|---|---|---|
| **A. 금 한 줄** | 이번 라운드 마지막 칸 뒤에 세로 선 | 판 그림에 낱장 하나 더 |
| B. 안 그린다 | 라운드가 바뀌는 것은 위쪽 `ROUND n` 이 알려 준다 | 없음 |

**A 를 권하지만 급하지 않다.** 넘김칸부터 넣고, 써 보고 헷갈리면 그때 금을
추가한다 -- 낱장이라 판을 다시 안 받아도 된다.

---

## 5. 왜 여섯인가

방 데이터에셋 열 개를 다 열어 본 값이다.

| 방 | 적 |
|---|---|
| `DA_TestMonster2_Stage1` · `DA_TestMonster_Stage3` | **3** |
| `DA_TestMonster_Stage1` · `_Stage2` | 2 |
| `DA_TestBoss_Stage1` · `DA_TestElite_Stage1` | 1 |
| 나머지 넷 | 0 (아직 안 채움) |

파티가 셋(`DefaultPartySize`)이므로 **셋 + 셋 = 여섯**.

### 여섯을 넘을 수 있는 길

| 무엇 | 막는 것이 있나 |
|---|---|
| **방에 적을 넷 이상** | **없다.** 배열이라 몇이든 들어간다 |
| **한 유닛에 턴을 더 준다** | 없다. `RegisterTurn(Owner, LifeCount)` 가 이미 됨 |
| 파티가 넷 이상 | `DefaultPartySize` 한 줄 |
| 소환 | 효과 레이어에 소환이 없다 |

둘째는 같은 유닛이 줄에 **두 번 뜬다.** 그게 맞다 -- "이 적이 이번 라운드에
두 번 움직인다" 를 그대로 보여 준다.

**넘김칸이 있으므로 여섯을 넘어도 이제 다 볼 수 있다.** 칸을 여덟로 늘려
초상을 68까지 깎을 이유가 없어졌다.

---

## 6. 지금 어긋나 있는 것

| | 값 |
|---|---|
| C++ 이 찾는 칸 | **여섯** (`TurnSlotCount = 6`) |
| 판 그림에 그려진 칸 | **다섯** |
| 게임플레이가 내려주는 수 | **전부** (안 자른다) |

여섯째부터는 값이 왔는데 그릴 자리가 없어 **말없이 잘린다.** 넘김칸이 들어가면
잘린 수가 화면에 뜬다.

---

## 7. 할 일

| # | 무엇 | 막힌 것 |
|---|---|---|
| 1 | 런타임: 창 · 넘김칸 · 누르면 옮기기 | **없음. 바로** |
| 2 | 판 그림 여섯 칸 + 양끝 넘김칸 | 시안 |
| 3 | 구역 `turn_portrait_06` · `end_left` · `end_right` 굽기 | 2번 뒤 |
| 4 | 방에 적을 넷 넣어 넘치는 것을 실제로 보기 | 없음 |
| 5 | (뒤로) 라운드 경계 금 | 4장 결정 |

**1번은 그림 없이 먼저 된다.** 지금은 다섯 칸으로 돌다가 그림이 오면 여섯이
된다 -- 칸 수를 세어 돌기 때문에 코드는 안 바뀐다. 넘김칸은 이름으로 찾으므로,
없으면 그냥 안 그린다.
