# 화면 기획 방법 — 판을 오려 붙이는 방식

> 작성: 박용수(UI) · 기준: 시안4 전투 HUD, 용병 선택 화면
> 짝 문서: [`UI_API_CONTRACT.md`](../../Source/P_RD/UI/Combat/UI_API_CONTRACT.md) (UI ↔ 게임플레이 경계)
> 이 문서는 **화면을 어떻게 기획해서 넘기면 되는가**를 다룬다.

---

## 0. 세 줄 요약

- 시안을 **조각내지 않고 그대로 오려** 쓴다. UI 코드가 모양을 만들지 않는다.
- 기획이 넘기는 것은 **그림 두 벌과 좌표 한 벌**이다. 그 외에 손으로 옮겨 적는 값은 없다.
- 칸 이름이 곧 코드 이름이다. **이름이 어긋나면 글자는 보이는데 게임 값이 안 들어간다.**

---

## 1. 이 방식이 뭔가

예전에는 UI 조각(모서리, 테두리, 채움)을 만들어 코드가 이어 붙이고 늘렸다.
그러면 시안의 느낌이 안 난다. 몰딩 두께가 달라지고, 비례가 어긋나고, 한 곳을
고치면 다른 화면이 같이 바뀐다.

지금은 반대다. **시안에 그려진 판을 그대로 오려 텍스처로 넣고, 원래 크기 그대로
놓는다.** 늘리지 않는다. 코드가 하는 일은 "어디에 놓을지"와 "그 안에 어떤 값을
쓸지"뿐이다.

```
시안 그림  ──오려서──▶  판 텍스처 14장  ──자리표대로──▶  WBP  ──이름으로──▶  런타임이 값 채움
```

그래서 **시안이 곧 결과물**이다. 시안과 화면이 다르면 그건 배치가 틀린 것이지
"구현 한계"가 아니다.

---

## 2. 기획이 넘기는 것

화면 하나당 세 가지다. 시안4는 이 셋이 다 갖춰져서 손으로 적은 값이 **하나도
없었다**.

| 넘기는 것 | 무엇인가 | 왜 필요한가 |
|---|---|---|
| **채운 시안** | 글자·아이콘·초상이 다 들어간 완성 그림 | 최종 모습의 기준. 캡처를 이것과 대조한다 |
| **빈 시안** | 같은 그림에서 **내용만 지운 것**. 판과 홈만 남는다 | 이게 실제로 쓰는 텍스처다 |
| **좌표** | 판이 화면 어디인지 + 판 안 칸이 어디인지, **칸마다 이름을 붙여서** | 자리표를 기계가 만든다 |

### 두 그림은 한 픽셀도 어긋나면 안 된다

같은 캔버스에서 내용만 지운 것이어야 한다. 다시 그리면 안 된다. 두 장을 겹쳐
**다른 자리가 곧 얹힌 내용**이므로, 어긋나면 아이콘 둘레에 유령 테두리가 남거나
엉뚱한 데가 뚫린다.

이 뺄셈 덕분에 아이콘·초상·보석을 따로 안 받아도 된다. 시안4에서 스프라이트
26장을 이렇게 떼어냈다.

### 좌표는 이런 모양이면 된다

```json
{ "file": "bottom_status_left.png",
  "source_box": [14, 765, 223, 923],
  "elements": [
    { "id": "party_portrait", "type": "portrait", "canvas_bbox": [31, 786, 65, 80] },
    { "id": "hp_bar",         "type": "progress_bar", "canvas_bbox": [128, 838, 79, 14] }
  ] }
```

`type` 은 `text / icon / portrait / progress_bar / badge / icon_group /
state_outline / state_overlay` 정도면 충분하다. 뜯는 쪽이 이걸 보고 "그림으로
뗄 것"과 "글자라 안 뗄 것"을 가른다.

---

## 3. 이름이 계약이다

**여기가 이번에 제일 크게 데인 곳이다.**

런타임 위젯(`UCombatLayoutHUDWidget`)은 위젯을 **이름으로** 찾는다. 못 찾으면
조용히 건너뛴다. 그래서 이름이 틀리면 이렇게 된다.

> 시안대로 다 보인다. 글자도 아이콘도 제자리다. **그런데 게임을 켜면 값이 안
> 바뀐다.** 시안에 적힌 숫자가 그대로 있다.

처음 시안4를 구울 때 칸 이름을 `ActionName` 으로 지었는데 런타임은
`CommandName` 을 찾고 있었다. 캡처만 보면 완벽했다.

### 그래서 기획이 칸에 이름을 붙일 때

- **이미 있는 이름을 먼저 찾아본다.** 아래 표가 현재 계약이다.
- 새 칸이면 이름을 정해서 같이 넘긴다. 그 이름이 코드에 그대로 들어간다.
- 같은 뜻의 칸에 화면마다 다른 이름을 붙이지 않는다.

### 현재 계약 (전투 HUD)

| 묶음 | 이름 | 개수 |
|---|---|---|
| 라운드/목표 | `RoundText`, `ObjectiveText` | 1 |
| 턴 순서 | `TurnToken_i`, `TurnPortrait_i`, `TurnName_i`, `TurnCurrent_i` | 6 |
| 명령 카드 | `CommandCard_i`, `CommandButton_i`, `CommandIcon_i`, `CommandName_i`, `CommandCost_i`, `CommandDamage_i`, `CommandCooldown_i`, `CommandSelected_i`, `CommandDisabled_i` | 6 |
| 아군 | `PartyCard_i`, `PartyPortrait_i`, `PartyName_i`, `PartyHPBar_i`, `PartyHPText_i`, `PartyStatus_i`, `PartyStatusIcon_i`, `PartyAPPip_i_j`, `PartySelected_i` | 3 |
| 적 | `EnemyPanel`, `EnemyPortrait`, `EnemyName`, `EnemyHPBar`, `EnemyHPText`, `EnemyDefense`, `EnemyForecast` | 1 |
| 턴 종료 | `EndTurnButton`, `EndTurnLabel` | 1 |

> 개수도 계약이다. 아군 3, 턴 6, 명령 6. 시안이 다섯 칸만 그려도 코드는 여섯을
> 찾고 없는 하나는 건너뛴다. **반대로 시안이 일곱을 그리면 일곱째는 영영 안
> 뜬다.**

---

## 4. 상태를 판에 그리지 마라

시안은 보통 "가장 보기 좋은 순간"을 그린다. 골라진 카드에 금테두리, 못 쓰는
카드는 어둡게, 세 번째 아군이 선택된 상태.

**그걸 판에 같이 그려서 넘기면 그 칸은 게임에서 영영 그 상태가 된다.**

용병 선택 화면이 실제로 그랬다. 6번 이력서가 늘 흐렸고 3번은 늘 금테두리였다.
시안을 다시 받아 상태 없는 판으로 갈아엎었다.

### 그래서

- **빈 시안은 "아무 일도 안 일어난" 상태**로 그린다. 전부 보통, 전부 안 골림.
- 상태 표시는 **낱장으로 따로** 준다. 금테두리, 도장, 가림막.
- 낱장이 없으면 코드가 만든다. 다만 시안과 다르게 생긴다.
- **테두리는 면이 아니라 테두리로.** 가운데가 찬 금색 사각형을 얹으면 밑의
  초상과 이름이 가려진다. 가운데가 비어 있어야 한다.

---

## 5. 화면 하나 만드는 절차

```
1. 시안 확정            채운 것 + 빈 것 + 좌표
2. 판을 아트로 넣기      prepare_hud04.py  → 자리표 자동 생성
                        import_hud04.py   → 텍스처 임포트
3. 스프라이트 뜯기       cut_hud04_sprites.py  (뺄셈)
4. WBP 굽기             build_hud04.py
5. 캡처해서 대조         P_RD.UI.CombatLayout.Capture → 1672x941 PNG
6. 게임모드에 물리기      set_combat_hud_class.py
```

3~5번은 몇 번이고 다시 돌린다. **자리표는 손으로 고치지 않는다** — 다시 만들면
사라진다. 고칠 게 있으면 시안이나 좌표를 고치고 다시 돌린다.

캡처는 시안과 **같은 크기(1672×941)** 로 나온다. 두 장을 겹쳐 보면 어긋난 데가
바로 보인다.

## 6. 누가 무엇을 정하나

| | 기획이 정한다 | 코드가 정한다 |
|---|---|---|
| **모양** | 판 그림, 색, 몰딩, 아이콘 | 없음 |
| **자리** | 판 자리, 칸 자리 | 없음 |
| **이름** | 칸 이름 (새 칸일 때) | 기존 이름은 코드가 소유 |
| **개수** | 시안에 몇 칸 그릴지 | 몇 칸까지 처리할지 |
| **값** | 없음 | 전부 (HP, 스킬, 이름, 턴) |
| **상태** | 상태별 낱장 그림 | 언제 어느 상태인지 |

시안에 적힌 "HP 90/100" 같은 숫자는 **자리를 보여주는 예시**일 뿐이다. 실제
값은 게임에서 온다. 그러니 시안의 숫자가 그대로 뜨면 **연결이 안 된 것**이다.

---

## 7. 겪은 것들 — 주의점

| 증상 | 원인 | 어떻게 넘기면 되나 |
|---|---|---|
| 특정 칸이 늘 선택/흐림 상태 | 상태가 판에 그려져 있음 | 빈 시안은 중립 상태로 |
| 글자는 맞는데 게임 값이 안 들어옴 | 칸 이름이 계약과 다름 | 이름을 미리 맞추거나 같이 넘김 |
| 아이콘 둘레에 유령 테두리 | 두 시안이 어긋남 | 같은 캔버스에서 지우기만 |
| 초상이 판 뒤로 숨음 | 판과 내용이 같은 층 | (코드 쪽 문제. 판 0 / 내용 10 / 표시 40) |
| 판이 4픽셀씩 밀림 | 자른 상자와 실제 그림 크기가 다름 | 여유를 뒀으면 그 값을 좌표에 적어줌 |
| 몰딩이 뭉갬 | 판을 늘림 | 늘리지 않는다. 크기가 다르면 다시 그림 |

---

## 8. 넘기기 전 체크리스트

- [ ] 채운 시안과 빈 시안이 **같은 캔버스**에서 나왔나
- [ ] 빈 시안에 **선택·쿨타임·흐림 같은 상태가 안 그려져** 있나
- [ ] 상태 표시를 **낱장으로** 같이 주나
- [ ] 좌표에 **칸마다 이름과 종류**가 붙어 있나
- [ ] 칸 이름이 기존 계약과 같은가. 새 이름이면 목록에 적었나
- [ ] 칸 **개수**가 계약과 맞나 (아군 3, 턴 6, 명령 6)
- [ ] 판을 자를 때 여유를 뒀다면 그 값이 좌표에 반영됐나

---

## 9. 이 방식으로 못 하는 것

정직하게 적어 둔다.

- **크기가 변하는 칸.** 판을 안 늘리므로 글자 수에 따라 늘어나는 상자는 못
  만든다. 긴 이름은 줄어들거나 잘린다. 늘어나야 하는 자리는 처음부터 넉넉히
  그려야 한다.
- **해상도별 다른 배치.** 지금은 1920×1080 캔버스 하나를 통째로 줄여 그린다.
  세로가 아주 긴 화면에서 아래위가 남는다. 화면 비율마다 배치를 바꾸려면 시안이
  그만큼 더 필요하다.
- **판 자체가 움직이는 연출.** 판은 자리에 붙어 있다. 슬라이드·팝 같은 연출은
  코드가 따로 만든다.
