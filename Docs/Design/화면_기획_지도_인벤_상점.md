## 0. 먼저 알아야 할 것 — 대부분 이미 있다

새로 만들 것이 적다. **뼈대는 다 서 있고, 시안4 판을 안 입었을 뿐이다.**

| 화면 | 지금 상태 |
|---|---|
| 지도 | `FrontendMapWidget` **1452줄**. 그래프 노드·간선까지 다 있다 |
| 스킬 | `SkillPanelWidget` **64줄**. 껍데기다. `EWorldWidgetType::SkillPanel` 자리만 잡혀 있다 |

**그래서 이 문서가 정할 것은 "무엇을 만드나"가 아니라 "무엇을 보여주고, 무엇을 정해야 하나"다.**

## 1. 글자 규칙 — 이것부터 정한다

다른 화면을 먼저 그리면 화면마다 글자 크기가 달라진다. 지금도 그렇다.

### 1.1 크기 다섯 단계로 고정

설계 캔버스 **1920×1080** 기준이다. 시안4는 1672×941 이라 `CHROME_SCALE = 1920/1672 ≈ 1.148` 을 곱해서 쓴다.

| 이름 | 크기 | 어디에 |
|---|---|---|
| **큰제목** | 40 | 화면 제목 ("상점", "전리품") |
| **제목** | 28 | 창 제목, 아이템 이름 |
| **본문** | 22 | 설명, 목록 줄 |
| **값** | 20 | 숫자, 체력, 가격 |
| **딱지** | 16 | 상태 뱃지, 단위, 각주 |

**여섯 번째를 만들지 마라.** 애매하면 가까운 쪽으로 붙인다.

### 1.2 색 넷

| 이름 | 색 | 쓰는 곳 |
|---|---|---|
| `TEXT_DARK` | `0.16, 0.11, 0.07` | **양피지 위** — 상단 바, 인벤, 상점 |
| `TEXT_PALE` | `0.98, 0.95, 0.88` | **어두운 판 위** — 스킬 카드, 적 창 |
| `TEXT_DIM` | `0.62, 0.58, 0.52` | 못 쓰는 것, 잠긴 것 |
| `TEXT_GOLD` | `0.94, 0.78, 0.35` | 돈, 강조 숫자 |

앞의 셋은 `build_hud04.py` 에 이미 있다. **`TEXT_GOLD` 만 새로 넣으면 된다.**

### 1.3 등급 색은 데이터가 들고 있다

`FShopItemUI.mRarityColor`, `FInventoryItemUI.mRarityColor`, `FRewardChoiceUI.mRarityColor` 가 **이미 색을 들고 온다.** 화면이 등급을 보고 색을 고르지 마라 — 받은 색을 칠하기만 한다.

**정할 것:** 그 색이 무엇인가. 지금 `ERarityType` 은 Common / Rare / Epic 셋이다.

> 제안: Common 회백 `0.78,0.78,0.75` · Rare 청색 `0.35,0.62,0.95` · Epic 보라 `0.72,0.42,0.95`
> 등급을 **테두리와 이름 글자에만** 칠한다. 바탕까지 칠하면 아이콘이 안 보인다.

### 1.4 숫자 쓰는 법

| 것 | 형식 | 왜 |
|---|---|---|
| 체력 | `90/100` | 빗금. 남은 것이 앞 |
| 돈 | `1,240` | 세 자리마다 쉼표 |
| 피해 | `8~14` | 물결. 하이픈은 뺄셈으로 읽힌다 |
| 쿨타임 | `쿨 2턴` / `남은 3턴` | 안 쓸 때와 쓰는 중을 글자로 가른다 |
| 행동력 | 아이콘 낱개. 아홉부터 `아이콘 x N` | 전투_기획 3장 |
| 없음 | `—` (em dash) | `0` 이나 빈칸이 아니다. 0과 "해당 없음"은 다르다 |

### 1.5 글자가 넘칠 때

**말줄임(`…`)으로 자른다. 줄이지 않는다.** 자동으로 글자를 줄이면 화면마다 크기가 달라져서 1.1을 정한 뜻이 없어진다.

- 이름은 **한 줄**. 넘치면 자른다. 전체는 꾹 눌러서 본다.
- 설명은 **최대 세 줄**. 넘치면 자른다.
- 자를 자리가 없으면 **판을 키우는 게 아니라 글을 줄인다** — 기획이 짧게 쓴다.

### 1.6 안 정해진 것

- [ ] 어떤 글꼴을 쓰나. 지금은 엔진 기본이다. 한글 자형이 나무 액자와 안 어울린다
- [ ] 숫자만 다른 글꼴을 쓰나 (숫자 폭이 일정해야 막대 옆에서 안 흔들린다)
- [ ] 외국어를 낼 건가. 낼 거면 지금 문장 길이를 1.5배로 잡아야 한다

## 2. 지도

### 2.1 지금 있는 것

`FrontendMapWidget` 1452줄. **노드·간선·현재 위치·이동 가능 판정까지 다 돼 있다.** `EWorldWidgetType::WorldMap` 으로 열리고, 주석에 이렇게 적혀 있다:

> MAP 버튼으로 열면 조회용, 전투 승리 후 열면 다음 방 선택용

**두 가지 모드가 이미 전제돼 있다.** 이걸 지키고 시작한다.

### 2.2 방 다섯 종류

`ERoomType` 에 있는 그대로다. 새로 만들 필요 없다.

| 종류 | 아이콘 제안 | 색 |
|---|---|---|
| `Treasure` | 열린 궤짝 | 금색 |
| `Shop` | 저울 또는 동전 주머니 | 초록 |
| `Monster` | 해골 | 회색 |
| `EliteMonster` | 뿔 달린 해골 | 주황 |
| `BossMonster` | 왕관 쓴 해골 | 붉은색 |

### 2.3 노드 상태 넷

| 상태 | 생김새 |
|---|---|
| **지나온 방** | 회색조. 채도 0. 위에 체크 표시 |
| **지금 방** | 금색 테두리 + 맥박(느린 밝기 변화) |
| **갈 수 있는 방** | 평상 + 흰 테두리. 간선이 밝게 |
| **못 가는 방** | 어둡게. 간선이 점선 |

### 2.4 정할 것

- [ ] **길이 갈라지나.** 갈라지면 몇 갈래까지. 안 갈라지면 지도가 한 줄이라 볼 이유가 적다
  > 권고: **2~3 갈래.** 로그라이크의 고르는 재미가 여기서 나온다
- [ ] **앞을 얼마나 보여주나.** 다음 방만? 끝까지?
  > 권고: **다음 두 칸까지 종류가 보이고, 그 뒤는 물음표.** 계획은 세우되 다 알지는 못하게
- [ ] **한 층에 방이 몇 개.** 지금 `StaticStageSpawnData` 에 값이 있는지 확인 필요
- [ ] 지도에서 **되돌아갈 수 있나.** 권고: 못 간다. 로그라이크다
- [ ] 지도가 **전투 중에도 열리나.** 상단 아이콘 넷 중 지도가 있으니, 열린다면 조회용

### 2.5 화면

- **전체 화면 팝업.** 배경 어둡게 깔고 그 위에 양피지 지도.
- 위에서 아래로 흐른다. 지금 층이 **아래**, 앞으로 갈 층이 **위**.
- 세로로 넘친다. **위아래 끌기**로 본다.
- 노드 하나 **96×96px**. 손가락으로 누를 수 있는 최소치다.

## 3. 스킬 탭

### 3.1 지금 있는 것

`SkillPanelWidget` **64줄. 사실상 비어 있다.** 여기가 가장 손이 많이 간다.

### 3.2 무엇을 보여주나

전투_기획 5.7장에서 명령 6칸을 이렇게 정했다:

| 칸 | 내용 | 바꿀 수 있나 |
|---|---|---|
| 1 | 이동 | ✕ 고정 |
| 2 | 평타 | ✕ 고정 |
| 3~5 | 스킬 3장 | ○ |
| 6 | 방어/대기 | ✕ 고정 |

**스킬 탭은 3~5번 칸을 바꾸는 곳이다.** 저장 데이터의 스킬 칸은 6개(`PlayerSkillSlot = 6`)라 여유가 있다.

### 3.3 화면 구성

파티가 셋이므로 **누구 스킬인지 먼저 고른다.**

```
┌─ 위: 아군 셋 탭 ────────────────┐
│  [기사]  [궁수]  [마법사]        │  ← 하나 고르면 아래가 그 사람 것
├─ 왼쪽: 지금 낀 6칸 ──┬─ 오른쪽: 가진 스킬 목록 ─┤
│  1 이동   (고정)      │  ▢ 화염구   2AP  쿨2     │
│  2 베기   (고정)      │  ▢ 치유     1AP  쿨3     │
│  3 [빈칸]  ←고르는 중 │  ▢ 돌진     1AP  쿨1     │
│  4 검기날리기         │  ▢ ...                   │
│  5 [빈칸]             │                          │
│  6 방어   (고정)      │                          │
└──────────────────────┴──────────────────────────┘
```

**왼쪽 빈칸을 누르고 → 오른쪽에서 고른다.** 두 단계다. 용병 고르기와 달리 여기는 두 단계가 맞다 — 어느 칸에 넣을지가 선택의 일부이기 때문이다.

### 3.4 정할 것

- [ ] **스킬을 어디서 얻나.** 전투 보상? 상점? 둘 다?
  > `FRewardChoiceUI` 에 `mKind` 가 있으니 보상으로 주는 길은 열려 있다
- [ ] **뺀 스킬은 사라지나 창고에 남나**
  > 권고: **창고에 남는다.** 사라지면 바꾸는 것이 도박이 되어 아무도 안 바꾼다
- [ ] **창고 칸 수 제한**. 무제한이면 목록이 끝없이 길어진다
- [ ] **직업 제한이 있나.** 기사가 화염구를 배울 수 있나
  > 권고: **있다.** 없으면 셋을 나눠 기른 뜻이 없다
- [ ] **전투 중에 바꿀 수 있나.** 상단 아이콘에 스킬이 있으니 열리긴 한다
  > 권고: **볼 수만 있고 못 바꾼다.** 바꿀 수 있으면 매 턴 최적해를 다시 짜게 되어 전투가 늘어진다

## 4. 인벤토리

### 4.1 지금 있는 것

`FInventoryUI` 가 이미 이만큼 들고 있다:

```
mGold  mLevel  mHP  mMaxHP  mEquipment[]  mSkills[]  mDetailText
```

`FInventoryItemUI` 는 `mKind  mName  mIcon  mItemIndex  mRarityColor`.

**한 사람 것**을 담는 모양이다. 파티가 셋이 됐으니 **여기를 손봐야 한다.**

### 4.2 장비 칸은 셋이다

`EEquipmentType` = **Weapon / Gloves / Boots**. 넷이 아니다.

> 시안4_1 요청서에 장비 슬롯을 **넷**(무기/방어구/장신구/부적)으로 적었다. **셋으로 고쳐 요청해야 한다** — 또는 기획이 넷으로 늘리기로 정하고 `EEquipmentType` 을 고친다.
> 권고: **셋 유지.** 늘리면 아이템 데이터를 그만큼 더 만들어야 한다.

### 4.3 화면

스킬 탭과 **같은 뼈대**를 쓴다. 위에 아군 셋 탭, 아래에 내용. 화면마다 다른 틀을 쓰면 익힐 것이 늘어난다.

```
┌─ 아군 셋 탭 ─────────────────────┐
├─ 왼쪽: 사람 ────┬─ 오른쪽: 장비 3칸 ─┤
│  초상            │  [무기]  검  Rare  │
│  이름 Lv.3       │  [장갑]  —         │
│  체력 90/100     │  [장화]  —         │
│  능력치 여섯 줄  ├─ 아티팩트 (파티 공용) ─┤
│                  │  ◇ ◇ ◇ ◇ ◇ ◇      │
└──────────────────┴────────────────────┘
                    돈 1,240
```

### 4.4 정할 것

- [ ] **돈은 파티 공용인가 각자인가.** 지금 저장은 **각자** 들고 있다 (`FPartyMemberPersistData.mMoney`)
  > 권고: **공용.** 상점을 파티 단위로 굴려야 선택이 생긴다. 그러면 저장 구조를 고쳐야 한다 — `URunPersistData` 로 옮긴다
- [ ] **장비를 파티원끼리 옮길 수 있나**
  > 권고: **된다.** 안 되면 잘못 준 장비가 영영 묶인다
- [ ] 같은 장비를 **여럿이 낄 수 있나** (수량 개념이 있나)
- [ ] **파는 것이 인벤에서 되나 상점에서만 되나**
  > 권고: 상점에서만. 인벤에서 팔면 "실수로 팔았다"가 생긴다

## 5. 아티팩트

### 5.1 지금 있는 것

`StaticArtifactData` = `mName  mIcon  mPrice  mRarityType  mStatModifiers  mStaticPassiveData`
`ArtifactComponentModel` 있음. **`PartyArtifactModel::AddArtifact(Data, PartyMembers)` 가 파티 전체를 받는다.**

**즉 아티팩트는 이미 파티 공용으로 설계돼 있다.** 이건 정할 필요가 없다 — 코드가 이미 답했다.

### 5.2 장비와 무엇이 다른가

| | 장비 | 아티팩트 |
|---|---|---|
| 누가 | 한 사람 | **파티 전체** |
| 칸 | 3칸, 갈아 끼움 | **쌓인다. 안 뺀다** |
| 설명 | `mDescription` 있음 | **없다** ← 문제 |

`StaticArtifactData` 에 **`mDescription` 이 없다.** 무슨 효과인지 화면에 쓸 글이 없다.

> **이건 데이터를 고쳐야 한다.** `mDescription` 을 추가하거나, `mStaticPassiveData` 에서 글을 만들어 내야 한다.
> 권고: **`mDescription` 추가.** 패시브에서 글을 뽑으면 효과를 바꿀 때마다 문장이 어색해진다.

### 5.3 화면

**따로 화면을 만들지 않는다.** 인벤토리 아래 칸에 붙인다 (4.3의 그림).

- 아티팩트 하나 **56×56px** 마름모 또는 원.
- 가로로 늘어놓고, 넘치면 줄바꿈.
- **꾹 누르면 상세** — 시안4_1 요청서의 상세창 규칙을 그대로 쓴다.
- 개수 제한 없음. 로그라이크에서 쌓이는 맛이 여기에 있다.

### 5.4 정할 것

- [ ] `mDescription` 추가 (위)
- [ ] **같은 아티팩트를 두 번 얻으면** 쌓이나 안 주나
  > 권고: **안 준다.** 쌓이면 균형을 두 배로 잡아야 한다
- [ ] 몇 개쯤 모으는 게 한 판 기준인가 (화면 칸 수가 여기서 나온다)
  > 권고: **한 판에 8~12개.** 두 줄이면 다 보인다

## 6. 상점

### 6.1 지금 있는 것

`FShopUI` = `mGold  mItems[]`
`FShopItemUI` = `mKind  mName  mIcon  mPrice  mDescription  mRarityColor  mIsAffordable  mIsSoldOut  mSlotIndex`

**`mIsAffordable` 과 `mIsSoldOut` 이 이미 있다.** 화면이 돈 계산을 하지 말라는 뜻이다 — 받아서 그리기만 한다. 전투 HUD의 `mIsUsable` 과 같은 규칙이다.

`ShopGameMode` 와 `StaticShopRoomSpawnData` 도 있다. `mPrimaryAssetTypes` 로 **무엇을 파는지**를 데이터가 정한다.

### 6.2 화면

```
┌─ 상점 ──────────────────── 돈 1,240 ─┐
│                                        │
│  [아이콘]  화염의 검      Rare    320  │
│            공격 +5, 화상                │
│  ─────────────────────────────────────  │
│  [아이콘]  치유 물약      Common   80  │
│            체력 30 회복                 │
│  ─────────────────────────────────────  │
│  [아이콘]  ~~강철 방패~~  품절         │  ← 회색조
│                                        │
├────────────────────────────────────────┤
│  [ 인벤토리 ]              [ 떠나기 ]  │
└────────────────────────────────────────┘
```

- **세로 목록.** 격자보다 낫다 — 이름·설명·값을 한 줄에 다 보여야 하고, 세로가 그걸 담는다.
- 줄 하나 높이 **120px** 정도.
- **못 사는 것**(`mIsAffordable == false`): 값만 붉게. 줄 전체를 흐리지 마라 — 살 수 있는지와 무엇인지는 다른 정보다.
- **품절**(`mIsSoldOut`): 줄 전체 회색조 + 이름에 취소선.
- **꾹 누르면 상세창.** 스킬/장비/아티팩트 각각의 상세창을 그대로 쓴다.

### 6.3 정할 것

- [ ] **몇 개를 파나.** 권고: **4~6개**. 한 화면에 다 보이는 수
- [ ] **되사기(판매)가 있나.** 있으면 값은 몇 %인가
  > 권고: **있다, 산 값의 50%.** 없으면 못 쓰는 장비가 짐이 된다
- [ ] **다시 채워지나.** 한 번 사면 그 방은 끝인가
  > 권고: **안 채워진다.** 채워지면 돈만 있으면 다 살 수 있어 고르는 뜻이 없다
- [ ] **값을 깎는 수단이 있나** (아티팩트로)
- [ ] **파는 물건을 어떻게 뽑나.** 층이 올라가면 좋은 게 나오나
  > `StaticShopRoomSpawnData.mStageLevel` 이 있으니 층 반영이 전제돼 있다

## 7. 순서 제안

**글자 규칙(1장)이 첫째다.** 이걸 안 정하면 나머지를 그린 뒤 전부 다시 손댄다.

1. **글자 다섯 단계 · 색 넷 · 숫자 형식 확정** — 화면 하나도 안 그리고 정할 수 있다
2. **등급 색 확정** (1.3) — 여섯 화면이 다 쓴다
3. **아티팩트 `mDescription` 추가** (5.2) — 데이터 일이라 UI 앞에 와야 한다
4. **돈 공용/각자 결정** (4.4) — 저장 구조가 걸려 있어 늦게 바꾸면 비싸다
5. **인벤토리** — 뼈대가 다 있고, 스킬탭·상점이 이 틀을 물려받는다
6. **상점** — 인벤토리 틀 재사용. `Mock*Driver` 로 게임 없이 먼저 시험
7. **스킬 탭** — 가장 새로 짜야 하는 곳
8. **지도** — 1452줄이 이미 도니, 시안4 판을 입히는 일이 대부분
9. **아티팩트 칸** — 인벤토리에 붙이는 것이라 마지막

## 9. 안 하기로 한 것

적어 둔다. 나중에 "왜 없지" 소리를 줄이려고.

- **격자 인벤토리(칸 채우기)** 안 한다. 장비가 3칸뿐이라 격자를 쓸 이유가 없다
- **드래그로 장비 옮기기** 안 한다. 모바일에서 드래그는 타일맵 끌기와 부딪힌다. **탭 두 번**으로 한다
- **아티팩트 빼기** 안 한다. 쌓이기만 한다
- **상점에서 값 흥정** 안 한다
