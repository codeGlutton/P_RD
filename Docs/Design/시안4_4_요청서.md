# 시안4_4 요청서 — 용병 상세창을 조각으로 나눠 달라

> 대상: 이미지 생성 담당 · 요청: 박용수(UI)
> 기준: [`시안4_3_요청서.md`](시안4_3_요청서.md) 로 받은 **용병 상세창(기사) 그림. 이 모양으로 확정한다.**
> 이제 그 한 장을 **런타임이 조립할 수 있는 조각으로** 나눠 달라.

---

## 0. 왜 조각으로 나누나

받은 그림은 **기사 한 명의 한 순간**이다. 게임에서는 이 창이 이렇게 달라진다.

| 것 | 왜 달라지나 |
|---|---|
| 기술 칸 | **5개일 수도 6개일 수도** 있다 |
| 행동력 보석 | **1개에서 10개+** 까지 |
| 체력·경험치 막대 | 매 순간 길이가 다르다 |
| 특성 | **0개일 수도** 있다 (지금 데이터엔 없다) |
| 창 세로 | 위 것들 때문에 **늘었다 줄었다 한다** |

그림 한 장으로는 이걸 못 한다. **틀과 조각으로 나눠야** 런타임이 있는 만큼 늘어놓는다.

---

## 1. 두 가지는 **빼고** 달라

| 뺄 것 | 왜 |
|---|---|
| **초상화** (기사 얼굴) | 게임에 이미 있다 — `KK_Face_Knight_HeadV2`. 용병마다 다른 그림이 들어간다 |
| **기술 아이콘** (칼·장화·주먹·검기·방패) | 게임에 이미 있다 — `T_skill_*`. 스킬마다 다른 그림이 들어간다 |

**둘의 "액자·틀"은 필요하다.** 그림만 빼고 홈과 테두리는 남겨 달라.

---

## 2. 납품 형식

### 2.1 폴더

```
시안4_4/
├ 전체/            받은 완성 그림 그대로 1장 (자리 재는 기준)
├ 틀/              늘어나는 것. 9슬라이스 정보 필요
├ 낱장/            안 늘어나는 것. 배경 투명, 여백 0
└ coordinates.json 모든 조각의 자리
```

### 2.2 낱장 규칙

- **배경 투명 PNG**
- **여백 없이 딱 맞게** 잘라라. 투명한 둘레가 남으면 자리 잡을 때 중심이 어긋난다
- 그림자는 조각 **안쪽**에만. 밖으로 흘리면 잘린다

### 2.3 틀 규칙 (9슬라이스)

늘어나는 조각은 **네 모서리를 지키고 가운데만 늘린다.** 그 경계를 알려 달라:

```json
{ "file": "frame_wood.png", "slice": { "left": 46, "top": 46, "right": 46, "bottom": 46 } }
```

### 2.4 좌표 json

받은 완성 그림(1장) 기준으로 **모든 조각이 어디에 놓였는지** 적어 달라.

```json
{
  "canvas": [971, 1652],
  "pieces": [
    { "id": "portrait_frame", "rect": [118, 110, 180, 180] },
    { "id": "hp_bar_empty",   "rect": [196, 518,  650,  46] },
    { "id": "ap_gem",         "rect": [508, 588,   34,  34] }
  ]
}
```

**글자 자리도 적어 달라.** 글자 그림은 안 쓰지만 **어디에 얼마만 한 글자가 들어가는지**는 알아야 한다.

## 3. 나눠 달라 — 목록

### 3.1 틀 (9슬라이스)

| # | id | 무엇 | 늘어나는 방향 |
|---|---|---|---|
| 1 | `frame_wood` | **나무 액자 + 네 모서리 금속판.** 안은 뚫려 있다 | 가로·세로 |
| 2 | `paper_fill` | **크림 양피지 바탕.** 결과 얼룩까지 | 가로·세로 |
| 3 | `card_frame` | **기술 카드 액자** (금테 + 어두운 안쪽). 아이콘 자리는 비었다 | 고정이어도 됨 |
| 4 | `slot_empty` | **빈 칸.** 점선 테두리 + 흐린 `＋` | 고정 |

> `frame_wood` 가 이 요청의 핵심이다. **창 세로가 내용에 따라 달라진다.**
> 모서리 금속판이 늘어나면 안 된다 — 그래서 9슬라이스 값을 정확히 알려 달라.

### 3.2 구분선·제목

| # | id | 무엇 | 크기 제안 |
|---|---|---|---|
| 5 | `divider_plain` | 얇은 가로 구분선 (초상 아래) | 가로 늘어남 |
| 6 | `divider_title_left` | 제목 띠 **왼쪽 화살촉** 장식 | 고정 |
| 7 | `divider_title_right` | 제목 띠 **오른쪽 화살촉** 장식 | 고정 |

「기술 (5/6)」 같은 제목은 **글자 + 양옆 화살촉**이다. 화살촉만 낱장으로 주면
런타임이 글자 길이에 맞춰 벌린다.

### 3.3 초상 자리

| # | id | 무엇 |
|---|---|---|
| 8 | `portrait_frame` | **금테 정사각 액자.** 가운데는 **뚫려 있어야 한다** — 게임 초상이 그 뒤로 보인다 |

**꽉 찬 판이 아니라 테두리만이다.** 가운데를 안 뚫으면 초상이 안 보인다.

### 3.4 직업 리본

| # | id | 무엇 |
|---|---|---|
| 9 | `ribbon_job` | 파란 리본 바탕 (양끝이 제비꼬리). **가로로 늘어나야 한다** — 「전사」와 「마법사」는 길이가 다르다 |
| 10 | `icon_job_knight` | 리본 왼쪽의 **방패 문장** |
| 11 | `icon_job_archer` | ○ 같은 자리에 들어갈 **활 문장** |
| 12 | `icon_job_mage` | ○ 같은 자리에 들어갈 **지팡이 문장** |

직업이 셋(기사·궁수·마법사)이라 문장도 셋 필요하다.
**리본 색도 셋으로 나눠 달라** — 기사 파랑 / 궁수 초록 / 마법사 보라.

### 3.5 막대 — 통과 채움을 따로

| # | id | 무엇 |
|---|---|---|
| 13 | `bar_track` | **빈 통.** 안쪽으로 파인 홈. 가로 늘어남 |
| 14 | `bar_fill_hp` | 체력 채움 (**초록**). 가로 늘어남 |
| 15 | `bar_fill_exp` | 경험치 채움 (**파랑**). 가로 늘어남 |
| 16 | `icon_heart` | 체력 하트 |
| 17 | `icon_shield` | 방어 방패 |

**채운 채로 그리지 마라.** 통과 채움이 따로여야 길이를 바꾼다.
통은 하나만 주면 된다 — 체력·경험치가 같은 통을 쓴다.

### 3.6 행동력 보석

| # | id | 무엇 |
|---|---|---|
| 18 | `ap_gem` | **청록 마름모 보석 한 개.** 안쪽에 빛 반사 |

**한 개만.** 열 개 붙은 그림으로 주지 마라 — 런타임이 남은 수만큼 늘어놓는다.

### 3.7 기술 카드 부품

| # | id | 무엇 |
|---|---|---|
| 19 | `card_name_attack` | 이름 띠 — **붉은색** (공격) |
| 20 | `card_name_support` | 이름 띠 — **초록색** (보조·이동·방어) |
| 21 | `card_name_spell` | ○ 이름 띠 — **보라색** (주문). 지금 안 쓰지만 `ESkillType` 에 있다 |
| 22 | `badge_ap` | 카드 아래 **파란 알약 배지.** 「AP 1」 글자는 런타임이 얹는다 |
| 23 | `card_cooldown_veil` | ○ 쿨타임 가림막. 카드 위에 덮이는 반투명 회색 + 모래시계 |
| 24 | `card_disabled` | ○ 못 쓰는 상태. 카드 전체 회색조 |

이름 띠는 **가로로 늘어나야 한다.** 「평타」와 「검기 날리기」는 길이가 다르다.

### 3.8 아래 칸

### 3.9 상태이상 (지금 그림엔 없다)

기사가 지금 상태이상이 없어서 안 그려졌다. **낱장으로 둘만 달라.**

| # | id | 무엇 |
|---|---|---|
| 29 | `icon_status_vulnerable` | **취약** — 금 간 보라 방패 |
| 30 | `icon_status_weakness` | **약화** — 아래로 꺾인 회색 화살 |

실제로 게임에서 쓰이는 상태는 이 둘뿐이다.

## 4. 크기 정리 — 늘어나는 것과 아닌 것

| 늘어남 | 조각 |
|---|---|
| **가로·세로** | `frame_wood` · `paper_fill` · `panel_inset` |
| **가로만** | `bar_track` · `bar_fill_hp` · `bar_fill_exp` · `ribbon_job` · `card_name_*` · `divider_plain` |
| **안 늘어남** | 나머지 전부 (아이콘·보석·배지·문장·빈 칸) |

**안 늘어나는 것을 늘리면 무늬가 뭉갠다.** 그래서 갈라 달라는 것이다.

---

## 5. 확인용 한 장 더

조각을 다 만든 뒤, **그 조각만으로 다시 조립한 그림 한 장**을 같이 달라.

받은 완성 그림과 나란히 놓고 **어긋난 데가 없는지** 볼 것이다.
시안4 때 조각을 4픽셀 어긋나게 잘라서 아이콘 둘레에 유령 테두리가 남은 적이 있다.

---

## 6. 이름 규칙

파일 이름을 이렇게 지어 달라. 게임에 넣을 때 그대로 쓴다.

```
KK_UNIT_frame_wood.png
KK_UNIT_bar_fill_hp.png
KK_UNIT_ap_gem.png
KK_UNIT_icon_status_vulnerable.png
```

`KK_UNIT_` + 위 표의 `id` + `.png`.

---

## 7. 다시 한번 — 하지 말 것

- **초상화와 기술 아이콘을 넣지 마라** (1장)
- **글자를 넣지 마라.** 이번엔 조각이라 글자가 없어야 한다. 자리만 좌표로
- **숫자를 넣지 마라.** 「AP 1」 「100/100」 「Lv. 3」 전부 런타임이 얹는다
- **막대를 채운 채로 주지 마라**
- **보석을 여러 개 붙여 주지 마라**
- 낱장에 **투명 여백을 남기지 마라**
- 그림자를 조각 **밖으로** 흘리지 마라

---

## 8. 이 창이 정해지면

용병 상세창의 조각은 **적 상세창·스킬 상세창·인벤토리에도 거의 그대로 쓰인다.**
액자·막대·보석·구분선·패인 상자가 공통이다.

그래서 이번 것만 제대로 나오면 나머지는 **바탕색과 아이콘만 더** 받으면 된다.
