# 전투 기획 — 시안4 HUD 가 정한 것, 정해야 할 것

> 작성: 박용수(UI) · 기준: 시안4 전투 HUD 인게임 반영, 파티 3인
> 이 문서는 **UI 가 확정된 뒤 게임 플레이 기획이 무엇을 정해야 하는가**를 다룬다.
> 화면을 만드는 방법은 [`화면_기획_방법.md`](../UI/화면_기획_방법.md) 에 따로 있다.

---

## 0. 세 줄 요약

- 화면이 정해지면서 **숫자 세 개가 고정**됐다. 아군 3명 · 명령 6칸 · AP 4칸.
- 지금 데이터는 **기사 한 명 분량만** 채워져 있다. 궁수·마법사 스킬은 전부 0이다.
- 제일 먼저 정할 것은 **AP 가 무엇인가**다. 화면은 4칸인데 데이터는 턴마다 10을 준다.

---

## 1. 화면이 확정한 것

이건 이제 기획의 전제다. 바꾸려면 시안부터 다시 그려야 한다.

| 항목 | 수 | 뜻 |
|---|---|---|
| 아군 | **3** | 여섯 중 셋을 골라 시작. 화면에 세 칸 |
| 명령 | **6** | 한 유닛이 한 턴에 고를 수 있는 것 = 이동 + 5 |
| AP 칸 | **4** | 한 유닛이 한 턴에 쓰는 자원 |
| 턴 줄 | **6** | 앞으로 올 차례를 여섯까지 보여줌 |
| 적 정보 | 1체 | 지금 보고 있는 적 하나. 체력·방어·**예상 피해** |
| 목표 | 1줄 | "모든 적 처치 — 남은 적 N" |

여기서 따라 나오는 것들:

- **턴은 유닛 단위로 섞인다.** 턴 줄에 아군과 적이 한 줄로 서 있다. "아군 페이즈 →
  적 페이즈" 가 아니다.
- **예상 피해를 보여주기로 했다.** 그러면 피해 계산이 **미리 알 수 있어야** 한다.
  치기 전에 못 보여주는 계산은 못 쓴다.
- **상태이상에 남은 턴이 붙는다.** "중독 2턴" 처럼 숫자가 보인다.
- **쿨타임도 턴으로 센다.** "쿨 2턴", "남은 3턴".

## 2. 지금 데이터에 있는 손잡이

기획이 값을 적을 자리는 이미 있다. 새로 만들 필요 없다.

### 유닛 능력치 (`UCombatTargetAttributeSet`)

| 이름 | 지금 쓰이나 | 비고 |
|---|---|---|
| `MaxHP` / `HP` | ○ | 화면 아군·적 칸 |
| `Defense` | ○ | 적 패널 "방어 0" |
| `Movement` / `MovementPoint` | △ | **이게 AP 다.** 3장 참고 |
| `RechargeMovement` | △ | 턴마다 회복량. 기사 = 10 |
| `AttackPoint` / `AttackFactor` | ? | 피해 계산에 쓸 자리 |
| `HealPoint` / `HealFactor` | ? | 회복 계산 |
| `DefensePoint` / `DefenseFactor` | ? | 방어 계산 |
| `MaxExp` / `Exp` / `Money` | ○ | 런 진행 |

### 스킬 (`UStaticSkillData`)

| 칸 | 뜻 | 화면 어디 |
|---|---|---|
| `mName` | 이름 | 카드 위 글자 |
| `mIcon` | 아이콘 | 카드 그림 |
| `mRequiredMovement` | **드는 AP** | 카드 오른쪽 아래 숫자 |
| `mCooldownDuration` | 쿨타임(턴) | "쿨 N턴" |
| `mAimPattern` | 조준 모양 | Single / Cross / Star / Square |
| `mAimRange` | 사거리 | |
| `mEffectPattern` / `mEffectArea` | 맞는 범위 | Single / Beam 등 |
| `mIsIndirect` | 곡사 | 장애물 너머 |
| `mIsPenetration` | 관통 | |
| `mSkillEffectLayers` | **무슨 일이 일어나나** | 아래 |
| `mSkillType` | Attack / Spell | |
| `mRarityType` | Common / Rare / Epic | |
| `mPrice` | 상점 값 | |

### 효과 레이어 — 이미 있는 여덟 가지

`Attack` · `Heal` · `GetDefense` · `GetMove` · `Agility` · `Fortification` ·
`Vulnerability` · `Weakness`

스킬 하나에 여러 장을 겹칠 수 있다. "피해 주고 + 나를 방어 올리기" 는 두 장이다.
**새 효과가 필요하면 레이어를 새로 만드는 것이고, 그건 코드 일이다.** 기존
여덟 가지 조합으로 되는지 먼저 본다.

## 3. 제일 먼저 — AP 가 무엇인가

**지금 화면과 데이터가 서로 다른 말을 한다.**

| | 값 |
|---|---|
| 화면 AP 칸 | **4** |
| 기사 `RechargeMovement` | **10** (난이도 3에서 8) |
| 스킬이 요구하는 AP (`mRequiredMovement`) | 이동 1, 베기 1, 검기 날리기 1 |

턴마다 10을 주는데 다 1씩 먹으면 한 턴에 열 번 움직인다. 화면은 네 번으로
그려져 있다. 셋 중 하나를 정해야 한다.

**A. AP = 행동 횟수 (권고)**
턴마다 4. 이동 1, 평타 1, 큰 기술 2. 화면 그대로다. `RechargeMovement` 를 4로
내리고 이동 비용을 1로 둔다. 계산이 눈에 보이고 카드 여섯 장 고르는 재미가 산다.

**B. AP 와 이동력을 나눈다**
이동은 칸 수(10)로 따로, 스킬은 AP(4)로. 규칙이 둘이 되고 화면에 이동 게이지가
하나 더 필요하다. **시안4에 그 자리가 없다.**

**C. 화면을 10칸으로**
시안을 다시 그려야 한다.

> 이걸 정하기 전에는 스킬 비용을 못 매긴다. 다른 결정이 전부 여기에 걸린다.

## 4. 지금 데이터의 구멍

확인한 그대로 적는다.

| 스킬 | AP | 쿨 | 사거리 | 상태 |
|---|---|---|---|---|
| 이동 | 1 | **2** | 1 | 쿨 2턴은 실수로 보인다. 이동을 두 턴에 한 번? |
| 베기 (기사) | 1 | 0 | 1 | 정상 |
| 검기 날리기 (기사) | 1 | 1 | 1 | 정상. 범위 Beam |
| 사격 (궁수) | **0** | 0 | **0** | **빈 껍데기.** 사거리 0이면 자기 칸만 |
| 빙결 (마법사) | **0** | 0 | **0** | **빈 껍데기** |

- 실제로 값이 들어간 것은 **기사 스킬뿐**이다.
- 궁수·마법사 스킬은 이름만 있고 전부 0이다. 이름도 이번에 제가 넣었다.
- **원거리 직업인데 사거리가 0** 이라 지금 상태로는 원거리가 성립하지 않는다.

시작 여섯 명도 아직 임시다. 체력만 다르고(100/120/80/75/70/85) 나머지는 기사
값을 복제했다. 폰도 여섯 다 기사다.

## 5. 정해야 할 것 — 목록

### 5.1 턴 구조

화면이 유닛 한 줄로 섞어 보여주므로 **개별 유닛 턴**이다. 정할 것:

- 순서를 무엇으로 정하나. 민첩? 고정? 매 라운드 다시 굴리나?
- 아군 셋의 순서를 플레이어가 바꿀 수 있나
- 죽은 유닛이 줄에서 빠지는 것을 어떻게 보여주나

권고: **고정 순서로 시작.** 민첩 기반은 턴 줄 예측이 흔들려서 예상 피해와 같이
쓰면 혼란스럽다. 나중에 `Agility` 레이어로 끼어들기를 붙이면 된다.

### 5.2 쿨타임의 기준

"쿨 2턴" 이 **그 유닛의 턴 2번**인지 **라운드 2번**인지. 파티가 셋이라 둘이
크게 다르다.

권고: **그 유닛의 턴 기준.** 라운드 기준이면 아군 수가 바뀔 때 체감이 달라진다.

### 5.3 피해가 범위인 이유

화면이 "피해 4~7" 로 그려져 있다. 범위를 쓸 거면 무엇이 흔드는지 정해야 한다.

- 주사위? (런 데이터에 `mDiceIds` 자리가 있다)
- 무기 편차?
- 치명타 별도?

권고: **주사위.** 이미 자리가 있고, 상점·보상으로 굴릴 것이 생긴다. 다만
**예상 피해는 범위로 보여준다** — 확정 숫자를 보여주고 다른 값이 나오면 버그로
읽힌다.

### 5.4 방어 계산

적 패널이 "방어 0" 을 보여준다. 뺄셈인지 비율인지.

권고: **뺄셈.** `피해 = max(1, 공격 - 방어)`. 예상 피해를 사람이 암산으로
검산할 수 있어야 화면의 숫자를 믿는다.

### 5.5 상태이상

지금 있는 것: `Vulnerability`(취약) · `Weakness`(약화) · `Fortification`(강화) ·
`Agility`(민첩) · `GetDefense` · `GetMove`.

정할 것:
- 각각 몇 턴 가나, 겹치면 쌓이나 갱신되나
- 화면 아군 칸에 **하나만** 보인다. 둘 이상 걸리면 무엇을 보여줄지
- 중독처럼 턴마다 깎는 것이 필요한가 (지금 레이어에 없다)

권고: **겹치면 턴 수만 갱신.** 쌓이는 규칙은 예상 피해 계산을 복잡하게 만든다.

### 5.6 명령 6칸을 무엇으로 채우나

권고안:

| 칸 | 내용 | AP |
|---|---|---|
| 1 | 이동 (고정) | 1 |
| 2 | 평타 (직업 고유, 고정) | 1 |
| 3~5 | 스킬 3장 — 런 중에 얻고 바꿈 | 1~2 |
| 6 | 방어/대기 (고정) | 1 |

고정 3칸 + 가변 3칸. 저장 데이터의 스킬 칸은 6개(`PlayerSkillSlot = 6`)라 그대로
맞는다.

### 5.7 파티 3인이 바꾸는 것

한 명일 때의 규칙을 그대로 셋에 곱하면 안 된다.

- **전멸이 패배.** (구현됨) 한 명 죽으면 그 방에서 계속 싸우나?
- 다음 방에서 살아나나. 부분 회복인가
- 돈·경험치는 파티 공용인가 각자인가. 지금 저장은 **각자** 들고 있다
- 적 수를 몇으로 잡나. 아군이 셋이 됐으니 지금 배치는 쉬워졌을 것이다

권고: **돈은 공용, 경험치·장비는 각자.** 상점을 파티 단위로 굴려야 선택이 생긴다.

### 5.8 목표

지금은 "모든 적 처치" 하나뿐이다. 칸이 한 줄 있으니 다른 것도 넣을 수 있다 —
N턴 버티기, 지점 도달, 특정 적 처치. 방 종류를 늘릴 때 같이 정하면 된다.

## 6. 균형의 출발점

정해진 것부터 역산한 제안. **검증 안 된 숫자다.**

| | 값 | 근거 |
|---|---|---|
| 턴당 AP | 4 | 화면 |
| 이동 1칸 | 1 AP | 한 턴에 최대 4칸 |
| 평타 | 1 AP, 피해 4~7 | 시안 |
| 중급 스킬 | 2 AP, 피해 8~14 | 시안 (방패 강타) |
| 큰 스킬 | 2 AP, 피해 12~18, 쿨 3 | 시안 (돌파 베기) |
| 아군 체력 | 70~120 | 지금 여섯 명 값 |
| 잡몹 체력 | 50 | 지금 값 |

여기서 나오는 감각: **평타로 잡몹 하나 잡는 데 8~12턴.** 너무 길다. 잡몹 체력을
낮추거나 피해를 올려야 한다. 시안의 숫자는 화면을 보기 위한 예시라 균형을 잰
값이 아니다.

## 7. 순서 제안

1. **AP 정의 확정** (3장) — 여기서 안 정하면 아래가 전부 막힌다
2. 궁수·마법사 스킬에 실제 값 넣기 — 사거리 0 부터
3. 쿨타임 기준·방어식·주사위 확정
4. 잡몹 체력/수를 파티 3인 기준으로 다시
5. 상태이상 지속·중첩 규칙
6. 명령 6칸 구성 확정 → 스킬 획득/교체 흐름

## 8. 합의 필요 (열린 질문)

- [ ] AP 는 행동 횟수인가 이동력인가 — **3장**
- [ ] 이동의 쿨 2턴은 의도인가 실수인가
- [ ] 쿨타임은 그 유닛의 턴 기준인가 라운드 기준인가
- [ ] 피해 범위를 흔드는 것은 주사위인가
- [ ] 방어는 뺄셈인가 비율인가
- [ ] 아군이 죽으면 그 방에서 끝인가, 다음 방에 부활하나
- [ ] 돈은 파티 공용인가 각자인가
- [ ] 턴 순서는 고정인가 능력치인가
