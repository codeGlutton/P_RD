# 0728 회의 결정 점검 — 프로젝트가 지금 어디까지 와 있나

> 작성: 박용수(UI) · 근거: 코드·자산을 직접 뒤진 결과
> 회의에서 정한 것을 **지금 프로젝트 상태**와 맞춰 본 것이다. 정한 것 옆에
> "그래서 무엇이 없나" 를 적었다.

---

## 0. 한눈에

| 정한 것 | 지금 |
|---|---|
| 이동 1칸 = 1 AP | ● 그대로. `mRequiredMovement` 로 이미 돈다 |
| AP 상한 없음, `@ × n` 표기 | ✕ **UI 를 고쳐야 한다.** 지금은 낱개 여덟 + `x N` |
| 크리티컬 배율 최종 ×1.5 고정 | ✕ 계산 자리가 없다 |
| 크리티컬 확률 = 유닛 스탯, 기본 10% | ✕ **그런 능력치가 없다** |
| 피해 min~max, 그 안에서 랜덤 | ✕ `mDamage` 한 값뿐 |
| 기믹(장판·가시)에도 피해·크리 | ✕ **기믹이라는 것 자체가 없다** |
| 기본 공격력·방어력 스탯 없음 | ● 확인했다. 원래 없다 |
| 관통 빔 / 비관통 빔 분리 | △ `EEffectPattern.Beam` 하나 + `mIsPenetration` |
| 적 다음 행동 미리보기 | ✕ UI 계약에 그런 칸이 없다 |
| 최대공격범위만 표시 (이동범위 안 봄) | ✕ 표시할 값이 안 온다 |
| `BP/UI` → `UI` 로 통일 | ✕ 아직 둘 다 있다 |

---

## 1. AP — 표기를 고쳐야 한다

**정한 것:** 이동 1칸 = 1 AP · 상한 없음 · `@ × n` 으로 표기 · 아티팩트로 최대 AP 증가

**지금:** 낱개 아이콘 여덟 개까지 그리고 아홉부터 `아이콘 x N` 이다.
`build_hud04.py` 의 `AP_PIPS = 8`, 런타임도 여덟을 찾는다.

**할 일**

- 낱개를 아예 버리고 **아이콘 하나 + `× n`** 한 가지로 간다
- 아군 칸의 `ap_gems` 구역을 그 크기에 맞게 줄인다 (지금 160×27 은 낱개용)
- `PartyAPPip_0~7` 여덟 개를 지운다. `PartyAPIcon` + `PartyAPText` 만 남긴다

> 전투_기획 3장에 "여덟까지 낱개" 라고 적어 둔 것을 지워야 한다. **그 문장은
> 이제 틀렸다.**

---

## 2. 크리티컬 — 놓을 자리가 하나도 없다

**정한 것**

| | 값 |
|---|---|
| 배율 | **최종 피해 × 1.5** 고정 |
| 확률 | **유닛 스탯**, 기본 10%. 아티팩트·스킬로 증가 |
| 적용 | 패시브 뺀 **액티브 스킬 + 기믹** |

**지금**

- `UCombatTargetAttributeSet` 에 **크리티컬 확률 같은 능력치가 없다.** 있는 것은
  `MaxHP/HP/Defense/Movement` 와 `*Point`·`*Factor` 여덟뿐이다
- `FSkillUI.mCriticalDamage` 는 **UI 계약에만** 있고 채우는 쪽이 없다
- 피해 계산(`TacticalEffect_HP.cpp`)에 크리 분기가 없다

**할 일 (게임플레이)**

1. `CriticalChance` 능력치 추가 · 기본 0.1
2. 피해 계산에 크리 분기 · 배율 1.5 고정
3. 아티팩트·스킬이 그 값을 올릴 수 있게

**할 일 (UI)**

- **용병 상세창에 크리 확률 한 줄.** 유닛마다 다르니 보여줘야 한다
- **스킬 상세창에는 안 적는다.** 배율이 고정이고 확률은 유닛 것이라, 스킬마다
  적으면 같은 말이 여섯 번 반복된다
- 크리가 터졌을 때 판 위에 뜨는 숫자를 다르게 (금색·크게)

---

## 3. 피해 min~max — 자산을 다 고쳐야 한다

**정한 것:** 액티브 스킬과 기믹에 min~max 를 따로 두고 그 안에서 랜덤

**지금:** `FSkillEffectLayer_Attack.mDamage` **한 값뿐이다.** 자동 생성된 설명도
`대상에게 8의 데미지를 입힙니다` 로 한 숫자다.

**UI 쪽은 준비돼 있다** — `FSkillUI` 에 `mDamageMin` `mDamageMax`
`mCriticalDamage` 가 이미 있다. 채우는 쪽만 생기면 된다.

> 모호재님이 목요일까지 스킬 DataAsset 을 고치신다고 했다. 그때 자동 생성
> 설명도 `8~12` 로 바뀌므로, **스킬 상세창의 글 덩이가 그대로 따라온다.**

---

## 4. 기믹 — 개념 자체가 없다

**정한 것:** 장판·가시박스 같은 기믹에도 피해와 크리티컬. 크리 확률은 기믹이
따로 가진다.

**지금:** `Trap` `Hazard` `Gimmick` 같은 것이 **코드에 하나도 없다.**
`ERoomType` 도 Treasure/Shop/Monster/Elite/Boss 다섯뿐이다.

**정할 것**

- 기믹을 **보드 액터**로 두나, **타일 속성**으로 두나
- 상세창을 주나. 준다면 적 상세창과 같은 틀인가
- 밟았을 때/턴 끝에 터지나

지금은 **이야기만 있고 물건이 없다.** UI 로 할 일이 없다.

---

## 5. 빔 — 관통/비관통을 어떻게 가르나

**정한 것:** 관통 가능 빔과 불가능 빔을 따로 만든다

**지금:** `EEffectPattern` 에 `Beam` 하나, 그 옆에 `mIsPenetration` 이 따로 있다.
실제 자산에서 관통을 켠 것은 **13개 중 둘**(연속 찌르기, 대검 베기)이다.

**두 갈래**

| | 어떻게 |
|---|---|
| **A. 지금 그대로** | `Beam` + `mIsPenetration` 조합. 자산 안 건드림 |
| **B. 나눈다** | `Beam` / `BeamPierce` 두 값으로. 조합이 사라져 읽기 쉬움 |

UI 는 둘 다 된다. **A 면 딱지 하나(`관통`), B 면 도해 색이 갈린다.**
정해 주시면 사거리 도해를 그쪽으로 맞춘다.

---

## 6. 적 다음 행동 미리보기 — 계약이 없다

**정한 것**

- 적은 **다음 스킬을 미리 정한다**
- 플레이어가 움직이면 **다시 계산해서** 보여준다
- **최대공격범위만** 칠한다 (이동범위는 안 보여준다)
- 기준은 **조준범위(사거리)**. 빔은 사거리 표시를 전체로
- 적 정보창에는 **다음 스킬 하나만** 뜬다

**지금:** `FCombatUITypes` 에 그런 칸이 **없다.** 적 패널은 체력·방어·예상 피해뿐이다.

**필요한 계약 (새로)**

```cpp
USTRUCT(BlueprintType)
struct FEnemyIntentUI
{
    int32              mUnitId;
    FText              mSkillName;      // 다음에 쓸 스킬
    UTexture2D*        mSkillIcon;
    int32              mDamageMin;
    int32              mDamageMax;
    TArray<FTileIndex> mThreatTiles;    // 칠할 칸
};
```

`mThreatTiles` 를 게임플레이가 계산해 내려주는 것이 낫다. **UI 가 사거리를
다시 세면 AI 판정과 어긋나는 날이 온다** — 지금 카드 켜고 끄는 것도 그래서
게임플레이에 맡겼다.

**그리고 이건 상세창이 아니라 판 위 표시다.** 타일을 칠하는 것이므로
`SRPGSkillBuildAction` 의 하이라이트와 같은 길을 쓰는 편이 낫다.

## 7. "적이 AP 가 모자라 못 때린다" 를 어떻게 보여주나

호재님이 짚은 것이다. 지금은 플레이어가 알 길이 없다.

**제안 셋**

| | 어떻게 | 값이 있나 |
|---|---|---|
| A | 적 정보창에 AP 를 그대로 보여준다 | ● `Movement` 로 있다 |
| B | 못 때리는 턴에는 위협 칸을 **안 칠한다** | ● 6장 계약이 생기면 |
| C | 적 머리 위에 "쉼" 표시 | ✕ 새로 만들어야 |

**B 가 가장 조용하고 확실하다.** 칠할 칸이 없으면 그 턴은 안 온다는 뜻이 된다.
A 를 같이 두면 왜 그런지도 읽힌다.

## 8. 폴더 정리

`Content/BP/UI` 와 `Content/UI` 가 **둘 다 있다.** `BP/UI` 에 옛 WBP 가 여섯 남았다
(`WBP_CharacterCard*`, `WBP_CharacterSelect`, `WBP_CombatActionPanel` …).

`UI` 로 통일하겠다고 했으니 옮겨야 한다. **참조가 걸려 있으니 옮기고 나서
빌드·시험을 돌려야 한다.** 제가 하겠다.

## 10. 제가 다음에 할 것 (UI)

순서는 값이 있는 것부터다.

1. **AP 표기를 `@ × n` 으로** — 값이 이미 있다. 바로 된다
2. **`BP/UI` → `UI` 폴더 정리** — 참조만 조심하면 된다
3. **용병 상세창에 크리 확률 줄** — 능력치가 생기면
4. **적 다음 행동 표시** — 계약(6장)이 생기면
5. **기믹** — 물건이 생기면

**1·2 는 지금 바로 할 수 있다.** 나머지는 게임플레이 쪽 값이 먼저다.

---

## 11. 확인 부탁

- **빔을 나누나 안 나누나** (5장) — 사거리 도해가 갈린다
- **`mThreatTiles` 를 게임플레이가 내려주나** (6장) — UI 가 세면 어긋난다
- **적 AP 를 적 정보창에 보여주나** (7장)
- **기믹을 언제 만드나** — 그 전까지 상세창 이야기는 미룬다
