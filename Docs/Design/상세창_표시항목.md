## 1. 지금 유일하게 꽉 찬 것 — 스킬 설명이 자동 생성돼 있다

이게 이번 조사에서 가장 큰 발견이다. `m_description` 이 **손으로 쓴 글이 아니라 데이터에서 만들어진 글**이다.

```
[행동력: 2 | 사거리: 1 (Cross) | 적용 범위: 1 (Single) | 쿨다운: 1턴]
■ 1타 모션:
- 대상에게 8의 데미지를 입힙니다.
- 취약 태그를 1 중첩 부여합니다.
```

13개 스킬 전부 이 꼴이다. 연타 스킬은 `■ 2타 모션:` 이 더 붙는다.

### 이게 뜻하는 것

**스킬 상세창은 이 글 한 덩이만 잘 그리면 절반이 끝난다.** 비용·사거리·범위·쿨·효과가 전부 그 안에 이미 들어 있다.

다만 **한 덩이 글이라 모양을 못 잡는다.** 두 갈래로 정할 수 있다:

| 안 | 방법 | 장 | 단 |
|---|---|---|---|
| **A** | 이 글을 **그대로 뿌린다** | 지금 당장 된다. 데이터가 바뀌면 글도 저절로 바뀐다 | 대괄호·`■`·`-` 가 그대로 보인다. 아이콘을 못 붙인다 |
| **B** | 값에서 **UI 가 다시 조립한다** | 아이콘·색·줄바꿈을 마음대로 | 글 만드는 규칙이 두 벌이 된다. 언젠가 어긋난다 |

> **권고: A 로 시작하고, 머리글(`[...]`)만 떼어 낸다.**
> 첫 줄의 `[행동력: 2 | 사거리: 1 | 적용 범위: 1 | 쿨다운: 1턴]` 은 **아이콘 네 개로 바꾼다** — 그 네 값은 계약(`mActionPointCost` 등)으로도 이미 오니까.
> 나머지(`■ 1타 모션:` 아래)는 **글 그대로** 뿌린다. 이 부분이 스킬마다 줄 수가 다르고, 그게 바로 "빈칸 파 놓으면 안 되는" 자리다.

## 2. 스킬 — 실제 값의 폭

23개 중 값이 든 13개만 봤다.

| 칸 | 실제 범위 | 상세창에 쓸 수 있나 |
|---|---|---|
| `m_required_movement` (AP) | **0 ~ 3** | ○ |
| `m_cooldown_duration` | **0 ~ 2** | ○ |
| `m_aim_range` | **1 ~ 2** | ○ |
| `m_effect_area` | **1 ~ 4** | ○ |
| `m_aim_pattern` | `SINGLE` / `CROSS` **둘뿐** | ○ (넷 중 둘만 씀) |
| `m_effect_pattern` | `SINGLE` / `BEAM` / `SQUARE` | ○ |
| `m_skill_motion_layers` | **1 ~ 2** (연타) | ○ |
| `m_is_penetration` | **13개 중 2개만** true | △ 켜진 것만 |
| `m_is_indirect` | **전부 false** | ✕ **그릴 일이 없다** |
| `m_price` | 대부분 0. 베기만 50 | ✕ 상점 붙기 전엔 못 쓴다 |
| `m_icon` | 있다 | ○ |

### 결정

- **곡사(`is_indirect`) 딱지를 만들지 마라.** 켜진 스킬이 하나도 없다.
- **관통 딱지는 만든다.** 2개가 쓴다.
- **조준 모양 도해는 `SINGLE`/`CROSS` 두 가지만 있으면 된다.** `STAR`/`SQUARE` 조준은 아무도 안 쓴다.
  다만 **효과 범위**에는 `SQUARE` 가 있으니(짓누르기) 그건 그려야 한다.

### 값이 비어 있는 스킬 10개

| 직업 | 스킬 | 상태 |
|---|---|---|
| 궁수 | 사격 · 난사 · 관통 사격 | **AP 0, 사거리 0, 모션 0.** 껍데기 |
| 마법사 | 화염구 · 유성 · 빙결 | 같음 |
| 공용 | (이름 없음) × 3 | **이름조차 비어 있다** |
| 기사 | (이름 없음) × 1 | 같음 |

**원거리 직업인데 사거리가 0이다.** 지금 궁수·마법사를 골라도 아무것도 못 한다.

## 3. 유닛 — 적과 아군이 다르게 채워져 있다

### 3.1 적 11마리

| 칸 | 실제 |
|---|---|
| `m_display_name` | 다 있다. **다만 영문** ("Eagle", "Skeleton Golem") |
| `m_description` | **11마리 전부 비어 있다** ← |
| `m_portrait` | 다 있다 (`KK_Face_Enemy_*`) |
| `m_icon` | **전부 None** |
| `m_skill_datas` | **1 ~ 3개** (대부분 1개) |
| `m_equipment_datas` | 0 ~ 1개 |
| `m_move_tendency` | **`MOVE_CLOSE` / `HOLD_RANGE` / `MOVE_AWAY`** ← 이게 쓸모 있다 |

### 3.2 아군 6명

| 칸 | 실제 |
|---|---|
| `m_display_name` | 한글로 다 있다 |
| `m_description` | **6명 다 있다.** "체력이 높고 크게 때린다" 등 한 줄 |
| `m_portrait` | 다 있다 (`KK_Face_*_HeadV2`) |
| `m_skill_datas` | **전부 5개** |
| `m_job_type` | KNIGHT 2 · MAGE 2 · ARCHER 2 |

**단, 같은 직업 둘이 스킬 5개가 완전히 같다.** 성직자와 마법사가 똑같고, 궁수와 도적이 똑같다. 야만전사와 기사도 똑같다. **폰도 여섯 다 `BP_KnightPlayerUnit_C` 다.**

### 3.3 그래서 정하는 것

**적 상세창에 띄울 것 (실제 값이 있는 것만):**

1. 초상 (`m_portrait`) — ○
2. 이름 (`m_display_name`) — ○ **영문이라 한글화 필요**
3. 체력 — ○ (런타임 값)
4. 방어 / 행동력 — ○ (런타임 값)
5. **행동 성향** (`m_move_tendency`) — ○ **"달려든다 / 거리를 지킨다 / 물러난다"**
6. **그 몹이 쓰는 스킬 1~3개** — ○ 아이콘 + 이름
7. ~~설명~~ — **전부 비어 있다. 칸을 만들지 마라**
8. ~~패시브~~ — **아래 4장**

**아군 상세창에 더 띄울 것:**

- 직업 (`m_job_type`)
- **한 줄 설명** (`m_description`) — 아군만 있다
- 스킬 5개
- 레벨 / 경험치 (런타임)

### 3.4 행동 성향이 "공격력"의 자리를 대신한다

유닛에는 공격력이 없다(1.4 아님 — 아래 5장). 대신 `m_move_tendency` 가 **"이 몹이 어떻게 굴 것인가"**에 답한다. 전술 게임에서 그건 숫자보다 쓸모 있다.

| 값 | 글 제안 | 아이콘 |
|---|---|---|
| `MOVE_CLOSE` | **달려든다** | 앞으로 향한 화살 |
| `HOLD_RANGE` | **거리를 지킨다** | 원 안의 점 |
| `MOVE_AWAY` | **물러난다** | 뒤로 향한 화살 |

**셋뿐이다. 낱장 세 개면 끝난다.**

## 4. 패시브 — 앞 문서의 결론을 뒤집는다

앞 판에서 나는 **"패시브가 상세창의 알맹이다"** 라고 썼다. **자산을 세어 보니 틀렸다.**

```
DA_TestPassive  ← 프로젝트 전체에 이것 하나
   m_description    (비어 있음)
   m_icon           None
   m_magnitude      5.0
   m_effect_class   TacticalEffect_AttackFactor_AddBase
```

**패시브 자산이 하나뿐이고, 그 하나도 설명과 아이콘이 없다.**

`FUnitDetailUI.mPassiveDescriptions[]` 는 계약에 있지만 **지금 채우면 빈 글이 온다.**

> **결정: 패시브 줄을 그리되 "있으면 그린다".** 지금은 아무 몹에게도 안 뜬다.
> 요청서에서 패시브를 **판에 파인 홈이 아니라 낱장 한 줄**로 받아야 하는 이유가 이것이다 — 0개일 때 홈이 남으면 흉하다.

## 7. 유닛 능력치 — 다시 확인

`UCombatTargetAttributeSet` 에서 **평소에 뜻이 있는 값은 넷뿐이다.**

| 이름 | 뜻 |
|---|---|
| `MaxHP` / `HP` | 체력 |
| `Defense` | **이번 턴만 유지되는 방어 스택** |
| `Movement` | **이번 턴만 유지되는 행동력(AP)** |
| `RechargeMovement` | 턴마다 받는 AP |

나머지 여덟(`*Point` 넷, `*Factor` 넷)은 **스킬 모션 동안만 유지되는 스냅샷**이거나 **버프가 얹은 추가분**이라 단독으로 못 보여준다.

**"공격력"이라는 능력치가 없다.** 피해는 스킬의 `mDamage` 가 정한다 — 자동 생성 설명에 `대상에게 8의 데미지를 입힙니다` 로 이미 적혀 있다.

## 8. 상태이상 — 태그는 이미 쓰이고 있다

앞 판에서 나는 "태그가 하나도 없다"고 썼다. **`DefaultGameplayTags.ini` 만 보고 한 말이라 반쪽이었다.**

자동 생성 설명에 이렇게 적혀 있다:

```
- 취약 태그를 1 중첩 부여합니다.   (강타, 해골 발차기)
- 약화 태그를 2 중첩 부여합니다.   (해골 강펀치, 조준 사격)
```

**실제로 쓰이는 상태는 둘이다 — 취약 · 약화.** ini 에 없는 건 코드에서 만들어 쓰기 때문이다.

`FStatusEffectUI` = `mTag` + `mStackCount`. **남은 턴이 없다.** 중첩 수만 있다.

> **결정: 상태 표시는 `아이콘 + 중첩 수` 다.** "중독 2턴" 같은 글은 지금 데이터로 못 만든다.
> 전투_기획에 적은 "상태이상에 남은 턴이 붙는다"는 **틀렸다. 고쳐야 한다.**
> 낱장으로 받을 것: **취약 아이콘 · 약화 아이콘, 둘.**

## 10. 요청서를 어떻게 고치나

### 빼는 것 (데이터 없음)

- 별 다섯 (유닛에 등급 없음)
- 능력치 여섯 줄 → **셋** (체력·방어·행동력)
- 속성 아이콘 여섯 (속성 없음)
- 상태 슬롯 다섯 → **취약·약화 아이콘 둘**
- **곡사 딱지** (쓰는 스킬 0개)
- 장비 슬롯 넷 → **셋**
- 효과 아이콘 여덟 → **실제로 설명 글에 나오는 것만**: 피해 · 방어 획득 · 회복 · 이동력 획득 · 취약 · 약화 = **여섯**
- 아티팩트 창 (자산 0개)

### 더하는 것 (데이터 있는데 빠뜨림)

- **행동 성향 배지 셋** — 달려든다 / 거리를 지킨다 / 물러난다
- **관통 딱지**
- **연타 표시** (`x2`)
- **효과 범위 `SQUARE`** 도해

### 방향

> **판은 액자와 바탕만. 줄과 칸은 전부 낱장.**
> 스킬 효과 줄 수(1~4), 몹 스킬 수(1~3), 상태 수(0~2), 패시브 수(0) 가 **전부 다르다.** 홈을 파면 반드시 남거나 모자란다.

## 11. 데이터부터 채워야 하는 것

그림보다 앞선다. 순서대로:

1. **궁수·마법사 스킬 6개** — 지금 전부 0이다. **원거리가 성립하지 않는다**
2. **이름 없는 스킬 4개** — 지우거나 채운다
3. **적 이름 한글화** — 11마리 전부 영문이다
4. **적 `m_description`** — 11마리 전부 비었다. 안 쓸 거면 상세창에서 뺀다
5. **장비 3개의 이름·설명·값** — 전부 비었다
6. **패시브 `m_description` 과 `m_icon`** — 하나뿐인 자산도 비었다
7. **아군 6명 차별화** — 지금 셋씩 짝지어 완전히 같다

## 12. 앞 판에서 틀렸던 것

정직하게 적어 둔다.

| 앞에 쓴 것 | 실제 |
|---|---|
| "패시브가 상세창의 알맹이다" | **자산 1개, 설명·아이콘 비어 있음.** 지금은 안 뜬다 |
| "상태이상 태그가 하나도 없다" | **취약·약화가 실제로 쓰이고 있다.** ini 만 보고 한 말이었다 |
| "효과 레이어 여덟 개를 다 달라" | 실제로 설명에 나오는 것은 **여섯** |
| "몹 스킬을 보여줄까" (열린 질문) | **보여줘야 한다.** 1~3개가 실제로 붙어 있다 |

그리고 아예 못 본 것이 둘 있었다: **자동 생성 설명**과 **행동 성향**. 둘 다 지금 가장 잘 채워진 값이다.
