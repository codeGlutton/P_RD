# 보스 처치 연출과 SVN 배포

## 동작

1~3스테이지 보스전 승리 시 네 컷 원화와 효과음을 스테이지별 타이밍으로 재생하고 기존 보상 화면으로 이어집니다. 일반 전투 승리와 패배는 건너뜁니다. 보상 UI와 지급 순서는 유지하며 보스가 쓰러진 배경으로 교체합니다. 3스테이지 보상 완료 후 런 기록을 정산하고 저장에 성공하면 타이틀로 이동합니다. 저장 실패 시 3초 뒤 재시도하며 런 기록은 중복 정산하지 않습니다.

재생 중 입력은 보상 화면으로 전달하지 않습니다. 완료는 한 번만 호출하며 월드 종료 시 음원·콜백·타이머를 정리합니다. 원화나 음원이 없으면 보상 흐름을 계속 진행합니다. 최초 로딩의 임시 텍스처 크기로 컷 영역이 잘못 계산되지 않도록 원본 크기를 사용합니다.

## 선행 변경과 드리프트

- 최신 develop의 저장 시스템과 보상 상자 분리 머티리얼 수정을 유지했습니다. 옛 SaveRun 구현을 되돌리지 않았습니다.
- develop에서 데이터 가져오기 명령의 unity 빌드 이름 충돌이 재현되어 #668의 브랜치를 기준으로 합니다. #668을 먼저 병합한 뒤 이 PR의 기준을 develop으로 변경합니다.
- 이전 튜토리얼 브랜치의 이력과 폐기한 StageVictory/EndingComic 시제품은 포함하지 않습니다.

## SVN r427

SVN 작업 사본 루트에서 다음 경로를 r427 이상으로 업데이트해야 합니다.

| 경로 | 내용 | 상태 |
| --- | --- | --- |
| OutSideAsset/AICreation/UI/StageVictory/BossCollapse | T_BossCollapse1~3, S_BossCollapse1~3: 6 uasset | 이번 코드가 사용 |
| OutSideAsset/AICreation/UI/StageVictory/T_StageReward1~3.uasset | 보스가 쓰러진 보상 배경 3장 | 이번 코드가 사용 |
| SourceArt/UI/BossCollapse | 네 컷 원화 3장, WAV 3개, 생성 기록·연결 문서 | 원본 보관 |
| SourceArt/UI/StageRewardBackgrounds | 배경 PNG 3장, 임포트 스크립트·설명 | 원본 보관 |
| SourceArt/UI/GameClearPartyV5 | PNG 20장, 자체 합성 음원 1개, 파티 미리보기 영상 4개, 배치·검증·연결 분석 | 게임 연결 전 원화 |

r427은 총 58개 파일입니다(런타임 uasset 9개, 원본·미리보기·문서 49개). 다른 UI 및 기존 용병 합성 시제품의 로컬 변경은 포함하지 않았습니다. SourceArt는 게임의 Content 경로가 아니며 게임 패키지에 이 미리보기 영상을 넣는 구조가 아닙니다.

## 남은 엔딩 작업

파티 엔딩 v5는 41개 조합/156개 순서 배치와 실제 알파를 검증한 PC 미리보기입니다. 아직 Unreal 텍스처 임포트나 엔딩 위젯 연결은 하지 않았습니다. 최종 보상 뒤 ClearRun 전에 유효한 파티 1~3명을 저장하고, 공통 배경 2장과 선택한 영웅별 조명 전후/뒷모습을 합성하는 위젯을 연결해야 합니다. 그때 엔딩 완료 뒤 현재 런 저장/타이틀 전환을 호출합니다.

## 검증 범위

Win64 Development Editor 빌드가 통과했고 P_RD.UI.BossCollapse 자동화 테스트 3개(Flow, Render, RewardBackground)가 모두 통과했습니다. 테스트는 승패·스테이지 분기, 실제 SVN 원화/음원, 입력 차단, 완료/취소, 16:9·넓은 화면·DPI 렌더, 보상 배경 교체 및 원래 배경 복원을 확인합니다.

실제 보스전을 끝까지 진행하는 전체 플레이, 최종 저장 실패 주입, 모바일 cook/기기 검증은 별도로 남아 있습니다.
