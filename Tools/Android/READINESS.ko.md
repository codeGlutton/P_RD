# Android 안정성 수정

전투 도중 저장하거나 앱을 닫으면 **전투방 입장 시점부터 재개**한다. 아군의 체력·소지품·재화와 두 랜덤 스트림을 하나의 런 스냅샷으로 복원하므로, 소모된 아군 상태와 새로 생성된 적이 섞이지 않는다. 전투를 완료한 뒤에는 완료 상태와 수령한 보상을 저장한다.

## 수정 범위

| 영역 | 동작 |
| --- | --- |
| Android 빌드 | Effekseer의 Windows 매크로 검사와 사용하지 않는 네트워크 기능 의존성을 정리한다. |
| 이펙트 쿠킹 | 마스킹된 Effekseer 소재 3종은 ES3.1에서 SceneDepth 페이드를 사용하지 않는다. Stage 3 던전 Niagara의 누락 모듈은 에디터·쿠킹 시 정확한 노드만 메모리에서 복구한다. |
| 이동된 에셋 | 눈보라·지진 스킬의 이름 변경 전 Niagara 경로와 테스트 적의 이동 전 기사 애니메이션 경로를 실제 변경 이력에 따라 연결한다. |
| 레거시 태그 | 거미 스킬의 Monster→Enemy 이름 변경과 VFX notify 태그를 리다이렉트한다. 별도로 존재하는 피해 처리 notify를 중복 호출하지 않는다. |
| 초상화 | 기사 데이터 두 종류에 남아 있는 삭제된 초상화의 패키지·오브젝트 경로를 현재 기사 초상화로 연결한다. |
| 저장 복구 | 체크섬·세대 번호가 있는 A/B 슬롯을 번갈아 저장한다. 손상된 최신 슬롯 대신 직전 유효 슬롯을 읽으며 기존 저장 형식도 읽는다. |
| 저장 실패 | 실제 저장 성공 여부를 반환하고, 실패 상태를 화면에 표시하며 자동 재시도한다. 읽을 수 없는 기존 저장을 빈 데이터로 덮어쓰지 않는다. |
| 앱 수명 주기 | 백그라운드 전환 시 대기 중인 저장 뒤에 현재 체크포인트를 기록한다. 상점 거래·휴식·보상 수령도 자동 저장한다. |
| 보상·포기 | 수령·품절·휴식 상태를 런에 보관하고 같은 보상의 재요청은 중복 지급하지 않는다. 포기는 런 종료 저장이 성공해야 진행한다. |
| 보상 화면 | 완료방을 재개할 때 현재 레벨·경험치를 표시하며 이미 지급한 경험치의 증가 애니메이션을 다시 만들지 않는다. |
| 종료 이력 | 런 종료와 사용자 이력 사이에 저널을 두어 슬롯 중 하나의 저장이 실패해도 이력을 복구한다. 같은 종료 ID의 이력은 중복 추가하지 않는다. |
| 터치 | 작은 핀치 이동을 누적하고, 두 번째 손가락이 참여하면 접촉이 모두 끝날 때까지 탭·롱프레스를 취소한다. 카메라와 HUD가 같은 드래그 임계값을 쓴다. |
| 모달·뒤로가기 | 설정창이 전장 제스처를 차단하고, Android Back/Escape는 최상위 화면의 확인창·패널부터 닫는다. |
| 화면 크기 | 주요 화면에 SafeZone을 적용하고 중첩 위젯의 이중 여백을 방지한다. 높은 해상도에서 DPI 배율을 1로 고정하지 않는다. |
| 영상 | 파일 내용으로 캐시를 검증하고 임시 파일 검증 후 교체한다. MP4 해상도는 미디어 데이터 전체를 읽지 않고 박스 위치를 찾아 읽는다. |
| 메모리·프레임 비용 | Android 품질별 스트리밍 예산을 적용한다. 타일 펄스는 실제 효과 타일만 갱신하고 렌더 상태 갱신을 묶는다. 전투 미리보기 복제·실행에 CPU 추적 구간을 추가한다. |
| 잘못된 전투 상태 | 속도로 턴을 만들 수 없는 상태에서 Shipping 게임 스레드가 무한 반복하지 않도록 종료 경로를 둔다. |
| 출시 검증 | 별도 업로드 키로 AAB를 만들고 서명·manifest·모든 네이티브 라이브러리 및 APK의 16 KB 정렬을 검사한다. Android 실제 컴파일이 실행되지 않은 CI는 통과로 처리하지 않는다. |

## 검증 경계

대상 기기와 목표 프레임률은 아직 정해지지 않았다. 스트리밍 예산은 초기 설정이며 발열·메모리 부족·전투 미리보기 지연이 모든 Android 기기에서 해결됐다는 의미는 아니다. `RDCombatPreviewDuplicate`, `RDCombatPreviewAction`, `RDCombatPreviewTurn`, `RDTileHighlightPulse`, `RDMediaCacheResolve` 추적 구간으로 기기별 비용을 측정할 수 있다.

외부 SVN 에셋이 필요한 프로젝트다. 검증용 에셋 변경은 별도 복사본에서 수행하며, 공유 SVN 원본에 UI 축소 설정을 저장하지 않는다. 밉맵 없는 UI에 `MaxLODSize`만 설정해도 크기가 제한되는 것으로 해석하면 안 된다. 큰 UI 두 종류의 Android별 축소와 실제 cooked 크기 확인 절차는 [Android 도구 설명](README.md)에 있다. 실제 준비 실행에서는 이미 설정된 Android 축소 배율(상자 아틀라스 5.328125, 지도 4.0)을 유지했으며 추가 축소는 하지 않았다.

Niagara 복구는 알려진 던전 시스템 경로·노드 경로·GUID와 비어 있는 함수 참조가 모두 일치할 때만 적용한다. `CascadeToNiagaraConverter`는 Editor 대상에서만 켜며 Android 게임에는 포함하지 않는다. 외부 SVN 원본을 저장하지 않고 매번 쿠킹할 때 재현한다. 적 Blueprint 7종의 오래된 CDO 속성 포인터 경고는 실제 능력치 객체와 스냅샷을 읽는 회귀 테스트로 검토했으며, 해당 경고만을 이유로 런타임 속성을 변경하지 않았다.

릴리스 서명 키, Android 빌드 러너, 저장소 필수 검사 설정 권한과 실기기는 외부 준비 사항이다. Draft 검토를 완료하기 전에 기기에서 설치·업데이트, 홈 화면 전환 후 프로세스 종료·재개, 느린 핀치와 다중 터치, 노치 영역, 영상 재생, 장시간 전투를 확인해야 한다. 출시 서명과 기기 검증이 완료되기 전에는 개발용 APK를 출시 산출물로 사용하지 않는다.
